# 一、宿主与插件（DSH 侧）

## 1.1 插件入口的形状（照这个写，别自创）

- **现象**：插件写完后"没装上"，或工具一个都没出现。
- **真因**：入口必须恰好导出 `name` / `inject` / `apply` 三样，宿主按名字装配。
- **修法/判据**：照抄现成插件。
- **读数原文**（`_tools/dsh-plugins/openmaic-course/lib/index.js`）：
  `:76 export const name = "dsh-openmaic-course"`、`:77 export const inject = ["tools","webServer"]`、`:507 export async function apply(ctx)`、`:83 const SEAM = "/dsh-openmaic"`、`:517 const register = (spec, execute) => { try { ctx.tools.register(makeTool({...spec, async execute(args){ return execute(args||{}); }})); } catch (error) { console.warn(\`[openmaic-course] 工具 \${spec.name} 注册失败：\`, String(error)); } }`。

★ 注意 `:517` 那个 `try/catch`：**注册失败只打一行 warn，工具静默消失**。看到"某个工具不存在"先翻启动日志里的 `注册失败`。

## 1.2 插件入口不能有顶层 await

- **现象**：启动日志出现一次 `Error [ERR_REQUIRE_ASYNC_MODULE]: require() cannot be used on an ESM graph with top-level await`，界面上表现为"插件没装上"。
- **真因**：宿主是 `require()` 装插件的，ESM 图里带顶层 await 就装不了。
- **修法/判据**：所有 `await import(...)` 挪进**函数体**；`apply` 本身可以是 async。惰性解析 `defineTool`（`await import("@deepseek-ai/dsh-tools")`）时尤其容易犯。
- **读数**：错误原文见上。

## 1.3 `parameters` 的形状：作者简写 vs 真 JSON Schema

- **现象**：插件本地注册通过，一到模型侧就 `400 Invalid schema for function 'xxx': schema must be a JSON Schema of 'type: "object"', got 'type: null'`，**而且连累整轮所有工具**（不只那一个）。
- **真因**：`defineTool` 吃 `{type:"json"}` 作者简写；`ctx.tools.register` 裸定义吃**真 JSON Schema**。`parameters` 本身是「参数名 → 该参数的 schema」映射，**不是**一份 JSON Schema。写成 `{type:'object',properties:{...}}` 会被当成名叫 `type` / `properties` 的参数而**整个工具被静默跳过**。
- **修法/判据**：自己写 `toJsonSchema` / `propertyToJsonSchema` / `paramsToJsonSchema`（`openmaic-course/lib/index.js` 自带这三只）。**必填写成参数属性上的 `required: true`**，顶层 `required: [...]` 也被拒。
- **读数原文**：解析器原话 `unsupported JSON schema: parameters.type must be a value schema object`；旧形状里那 4 个报 `parameters.properties.type must be string/number/integer/boolean/null/array/object/json, or use oneOf`。
- 探针 `_tools/dsh-plugins/probe-define-tool.mjs`：照此改完 4 个工具后 **5/6 收**（第 6 个是旧形状对照，本该被拒）。
- ★「别写 `additionalProperties: false`」是**症状不是规定** —— 真原因是整个 `parameters` 被当成了参数名。

## 1.4 宿主注册工具时不校验 `parameters`

- **现象**：参数写错形状，本地**静默通过**，到模型侧才炸，且连累整轮。
- **真因**：`ctx.tools.register` 只校验 `output.schema`，不校验 `parameters`。
- **修法/判据**：注册完自己跑一遍 `assertSupportedJsonSchema(tool.parameters)`。
- **读数**：无独立计数（属机制性结论，已由 1.3 的探针 5/6 间接实测）。

## 1.5 部署副本是 copy，不是 junction —— 改源不会生效

- **现象**：改了 `_tools/dsh-plugins/` 里的源码，行为不变。
- **真因**：`~/.dsh/profiles/desktop/node_modules/` 下这两个插件是**复制体**而不是链接。
- **修法/判据**：改源之后**手动同步到 profile + 重启**。
- **读数原文**：`dsh-openmaic-course` 与 `dsh-openmaic-local-capabilities` 都是 `DIRECTORY (copy)`（`test -L` 为假）。该 `node_modules` 下唯一的 `<JUNCTION>` 是 `probe-seat` → `D:\文档\jelly_ware\program\engineering\gates\diag\probe-seat`，mtime 2026/10/17 21:51。
- ★ **旧结论「`file:` 依赖装出来是 Junction，改源即生效」已被推翻** —— 那对**别的**包成立，对这两个 openmaic 插件不成立（见上）。客户端半本来就一直是预打 bundle，改 `lib/client.src.js` 后必须 `node build.mjs` 重打。

## 1.6 Junction 安装会让插件解析不到 `@deepseek-ai/*`

- **现象**：走 `file:` 依赖装成 junction 时，插件里 `Cannot find package '@deepseek-ai/dsh-tools'`。
- **真因**：Node 按**真实路径**向上找 `node_modules`，junction 指向的源目录在 profile 之外。
- **修法/判据**：插件退回裸 `ctx.tools.register`，就得自己把作者简写翻成 JSON Schema（即 1.3 的 `paramsToJsonSchema`）。

## 1.7 修完必须重启才作数

- **现象**：代码改完了，行为还是旧的，每一轮报同一个错但 `request_id` 是新的。
- **真因**：宿主半只在**启动时**装配。
- **修法/判据**：判断"没修好"之前，先看进程启动时间 vs 代码 mtime。
- **读数原文**：一次实测里进程 `0:06:02` 启动、代码 `0:22:40` 才改完 ⇒ 每轮都用旧 schema。

## 1.7.1 2026-10-30 晚：进程启动时间 17:22:38 / 部署副本 mtime 18:33:56（**旧码仍在跑**）

- **读数原文**：`Get-CimInstance Win32_Process -Filter "Name like '%DeepSeek%'"` → `ProcessId 24864 / 2544 / 2572`，`CreationDate` 全为 `2026/10/30 17:22:38`（±1s）；`C:/Users/asus/.dsh/profiles/desktop/node_modules/dsh-openmaic-course/lib/index.js` 的 mtime 是 `2026-10-30 18:33:56.445675700 +0800`，比进程晚 **71 分钟**。
- **行为证据（同一个 live seam）**：`openmaic_patch_stage(dryRun:true, textsJson 把 `<strong>` 换成 `<b>`)` → `changes: ["text_x7zotvnD 文字改"]`，但 `diff.counts` 里**没有 `markupChanged` 这个键**（`{before:10, after:10, textChanged:0, restyled:0}` 其余全 0），`diff` 里也没有 `markupChanged` 数组 ⇒ 跑的是**修 `markupChanged` 之前**的宿主半。

- **结论**：`markupChanged` 这个修复**还没有在 DSH 里生效**，必须重启 DSH 后复验同一调用应出现 `markupChanged: 1` 且 `textChanged: 0`。
- ★ **这是 §1.7 判据的第二次实战命中**：判「没修好」之前，先比进程启动时间与代码 mtime。

## 1.12 插件市场（dshmarket）四条误判/风险

读数均为 2026-10-24 实测：

1. `duplicateEntryIdsAreFatal()` 从 pnpm-lock 查 **loader 版本**，而 loader 是**宿主提供**的 ⇒ 永远查不到、永远判"致命"。实际 `dsh --profile X --dump-config` exit=0，真因是两份补丁都 insert 了 `schedule` / `ui-schedule`。
2. 它在 `file:` 依赖上的处置会**清空源目录**（`_refs/dsh/dsh-ops-main` 被清成空目录）。
3. 声明与 lock 不一致时（`package.json` 0.3.0 vs `pnpm-lock` `^0.4.1`）frozen-lockfile 直接失败 ⇒ 任何"更新"都被回滚。
4. 在插件管理器里连续点安装会起**并发 pnpm**，互相踩 `node_modules`。

## 1.13 DSH Web 的认证墙：**`/plugins/*` 404 不代表插件没加载**

- **现象**：`curl http://127.0.0.1:<port>/plugins/dsh-openmaic-course/...` 全 404，容易误判成「插件没装好」。
- **真因**：整个**静态资源面在签名 cookie 认证之后**。401 文案逐字：
  `dsh web authentication required; reopen the URL printed by dsh web.`
  `BrowserAuth` 用签名 cookie，secret 存在 credential 记录里。
- **反证**：连**确定能跑**的 `dsh-client-ui-workbench-panel` 在同样 curl 下也 404 ⇒ 404 是认证的后果，不是加载的后果。
- **两条旁证限制**：进程名是 `DeepSeek Harness`（**不是 `node.exe`**，按 node 找找不到）；
  `browse_page` 对**回环地址**直接回 `blocked` ⇒ **无法用工具看面板，只能靠人眼**。
- **判据**：要验插件在不在，**别 curl**。要么看工具清单（12 个工具在不在），要么看 live seam
  `GET /dsh-openmaic/active|courses|scenes|page|text` 是否回结构化数据 —— 那是路由层的，不走静态资源面。

# 二、内容与渲染

## 1.14 侧栏「课件 课件」是**图标槽塞了文本**，不是 label 重复

- **现象**：DSH 侧栏一行渲染成「课件 课件」。看图会以为是 label 写重复了。
- **真因**：`sidebar.panellist` 的注册是 `register(spec, 图标渲染函数)` —— 第二个参数**就是图标槽**。原来写的是
  `() => h('span', { style: { fontSize: 12 } }, '课件')`，而 `label` 又是「课件」⇒ 图标 + 标题各一个「课件」。
- **修法**：图标槽换成真图标（`MarkIcon`），label 才是文字。
- ★ **这个槽位没有独立的 icon 字段**：核心行条目只有 `{id, order, label}`（抄自 `gates/diag/panel-plugin` 的
  `makeIcon(paths, round, seatKey)`），图标只能由第二个参数返回。
- **品牌来源**：`lib/brand/brand-config.ts` 的 `DEFAULT_BRAND` —— `productName: 'OpenMAIC'`、`markSrc: '/openmaic-mark.png'`
  （128×128 RGBA）、`themeColor: '#722ed1'`。标签用 `productName`，图标用 `markSrc`，别自创。
- **做法（不重画）**：官方标识是带字形的立方体，手描 SVG path 会失真 ⇒ 直接内嵌 PNG：
  裁透明边（`getbbox()` = `(12,9,116,120)`）→ 补方 → LANCZOS **48×48** → PNG optimize（4875 B / b64 **6500 字符**）。
  48 而不选 32/64：32 在 16px 槽会糊，64 的 b64 是 9780 字符太长。**48px 在 16px 槽位是 3× 采样**，实测肉眼可辨。
- **内嵌形态**：`lib/mark.js` 导出 `OPENMAIC_MARK_URI`（值形如 `data:image/png;base64,<6500 字符>`）；`icon.svg` 用同一个 data URI
  包 `<image>`；`package.json` 加 `"icon": "./icon.svg"`（与 panel-plugin 同构）。
- **判据（可复制）**：`renderToString` 渲 `sidebar.panellist` 槽，应得
  `<img src="data:image/png;base64,..." width="16" height="16" aria-hidden="true" style="flex:none;display:block;vertical-align:-2px"/>`；
  旧文本图标的 `fontSize: 12 }, '课件'` 在产物里计数应 **0**。
- ★ **解码回比对的判据**：把 `mark.js` 里的 b64 解回 PNG 与「官方 PNG 裁边补方 LANCZOS 48」逐像素比较，
  实测 **identical**（48×48、1416 个非透明像素）—— 这样才证明「没走样」，光看图不算。

## 1.15 五个诊断模块接进 DSH：**纯算术能搬，取数必须留在仓里**

- **背景**：B3 要把 OpenMAIC 的计划检查 / 版面检查 / 覆盖缺口 / 写后诊断 / 课程审计搬进 DSH。
  五个都是**纯函数**（不碰库、不起渲染、不花模型），但它们住在仓里的 TS 里。
- ★ **插件进程不能直接 import 仓里的 TS**：插件目录（`_tools/dsh-plugins/openmaic-course/`）
  没有 `node_modules`，从仓外解析 `@/` 别名与 `pg` 都会失败 ⇒ 现起一个桥子进程。
- **分工**（这是整段的关键）：`index.js` 用 `db.mjs` **取数** → JSON 走 **stdin** 交给桥 →
  桥只算数、结果一行 JSON 走 stdout。桥**不碰库**，所以同一段 stdin 永远得同一段 stdout（可复算）。
- ★ **四个必须记住的坑**（全部实测）：
  1. `node_modules/.bin/tsx` **不是 JS**，是 shell 脚本 ⇒ Windows 上 `node <它>` 直接
     `SyntaxError: missing ) after argument list`。必须点名真实入口 `node_modules/tsx/dist/cli.mjs`
     且显式 `--tsconfig <仓根>/tsconfig.json`、cwd 是仓根。
  2. **`@/` 别名下不能命名导入**：`import { auditCourse } from '@/lib/quiz/course-audit'` 报
     `does not provide an export named 'auditCourse'`，命名空间里只有 `['default','module.exports']`。
     必须 `import * as m` 再 `m.default ?? m` —— 五个模块全都这样解。
  3. `formatCoverageGaps` 吃的是**扁平 `CoverageGap[]`**，不是 `PageCoverageReport[]`。直接塞
     reports 会报 `Cannot read properties of undefined (reading 'join')`（它按 `gap.sources.join` 渲染）。
     修法 `scopedReports.flatMap(r => r.gaps)`。
  4. `spawnSync` 默认 **maxBuffer 1 MB**，而一门 90 页读全是 **1.6 MB** ⇒ 报
     `spawnSync … ENOBUFS`，看上去像读库失败。`readDb` 显式给 64 MB。
- **计划信封不在 `document_stages.data` 里**：那张表的键只有
  `id/name/agentIds/createdAt/updatedAt/dslVersion/description/generatedAgentConfigs`。
  计划在独立的 **`document_outlines(stage_id, data jsonb)`**。实测 9 门课里 4 门有、5 门是空数组或没有行。
  ⇒ `plan` 报 `planPages 0` 时**不是「计划没问题」，是没计划可查**，工具里必须写明这句。
- **`document_scene_revision` 只有 `rev` 号没有 `data`** ⇒ 拿不到旧版本内容，"这次改动了什么"算不出来。
  那件事只能由 `patch_stage` 当场回的 `layoutDelta` 负责（它手上同时有改前改后两份）⇒
  `openmaic_scene_diagnostics` **不接 `previousSceneId`**，不假装能算。
- **读数**（`stage-GYvpbYB_aN`，90 页真实数据；每起一次子进程 0.6–1.2 s）：

## 1.16 阶段冻结接进 DSH：**守卫不复刻，直调仓内实现；写入顺序是对错的分水岭**

`openmaic_plan_freeze`（第 13 个工具）把 `plan_freeze` 的五个动作（status / add / backfill /
freeze / revise）搬到 DSH。做法**不是**重写一份分支逻辑，而是让桥子进程直接
`buildPlanFreezeTool({ loadOutline, loadPages, saveOutline })` —— 传进去的 `saveOutline`
只是把新计划**记在变量里**，真正的写库由 `lib/index.js` 收尾。这样四道守卫的措辞与
分支和仓内**逐字一致**，不会两边走样。

**为什么不复刻**：`add` 的覆盖守卫有「三条出路」的长文案（页号顺延 / 同标题重写 / 用
`revise` 覆盖），`freeze` 的规格闸要报 `gaps.samples`，`revise` 的「没冻结不许修订」
要和 `reason` 必填串起来。任何一条抄走样，DSH 侧就会给出与自托管 OpenMAIC 不同的建议 ——
而模型会照着那个建议去改学习者的课件。

**★ 写入顺序（先计划、后状态）是对错分水岭**：`revise` 同时改两处 —— `document_outlines`
里的计划信封、和 `data/plan-freeze/<stageId>.json` 里的冻结状态。顺序反过来会留下
「状态说冻结了 N 条、计划里却是旧的 M 条」的错位；而正方向失败只是「冻结没生效」，再跑
一次 freeze 就恢复。所以计划写失败时**必须停在原地、不碰状态文件**。
打桩验证（把 `writeOutline` 强制返回失败）：`ok:false`、`step:"写计划失败，冻结状态未动"`、
`stateWrite: undefined`、状态文件逐字节未变、`revision` 仍为 3。

**★ 出错就什么都不交**：试跑时踩到 —— `revise` 没写 `reason` 被拒，但临时目录里那份
state 是**为了让工具读得到而预先写进去**的，于是 `nextState` 把旧状态原样带回来了，
index.js 照着写一次，看上去像「改成功了」。这是幂等的（写回的是同一份内容），但语义错：
被拒的动作不该产生任何落盘。齐一律收在桥里：`isError ⇒ nextOutline / nextState 皆 null`。

**★ async 命令必须 await**：`plan-freeze` 是唯一返 Promise 的命令。`main()` 里不 `await run(input)`
的话，`JSON.stringify(Promise)` 会**静默写出 `{}`** —— 看上去像「命令没有输出」，不是报错。

**落盘三处规则（插件侧复刻，必须与仓内一致）**：
- 冻结状态目录 = `OPENMAIC_PLAN_FREEZE_DIR` ?? `<OPENMAIC_ROOT>/data/plan-freeze`
  （`plan-freeze-store.ts:30`）；文件名 = `stageId.replace(/[^A-Za-z0-9_-]/g, '_') + '.json'`（`:40`）。
  两处不一致就会出现「读的和写的不是同一个文件」。
- 写状态走**原子写**（`.tmp` → `rename`），与 `writePlanFreeze` 同形。
- 计划表 `document_outlines(stage_id text PK, data jsonb)` **只有两列**，整封 upsert：
  `insert … on conflict (stage_id) do update set data = excluded.data`。

**`unit` 参数是值不是标签**：传 `unit: "Unit 1"` 会拼成 `【Unit Unit 1】`（`outlineEntryFromPlanEntry`
自己加 `Unit ` 前缀）。工具描述里已写「只写值」。

**端到端（真库 `stage-0O5fLNmbe4`，7 页、原本计划 0 条未冻结）**：
`backfill` ⇒ 7 条入 `document_outlines`（`entries:7`）· `freeze` ⇒ 状态文件 144 B、`frozen:true`
· `revise removeOrders:[7]` ⇒ 库里 6 条、`revision` 0→1。
**全程还原**：outline 写回原信封（`json.dumps(sort_keys)` 逐字节相同，0 条）、状态文件删除。
三个守卫反向验证：`add` 占别人的号 ⇒ `isError`+`nextOutline:null`；`revise` 空 reason ⇒ `isError`；
`freeze` 空计划 ⇒ `isError`。不存在 stageId ⇒ `没有这节课`，什么都不写。

## 1.19 `@openmaic/*` 的 `exports` 只有 `import` 条件 —— tsx 加载它必然失败

**现象**：桥里 `await import('@/lib/server/agent-runtime/curriculum-tools')` 报
`ERR_PACKAGE_PATH_NOT_EXPORTED No "exports" main defined in …/node_modules\@openmaic\storage\package.json`。

**真因**（不是"Node 版本不对"、也不是"包没装"）：`packages/@openmaic/dsl/package.json` 与 storage 的
`exports` 字段只有 `"import"` 一个条件，**没有 `"require"`**：

```json
{".": {"types": "./dist/index.d.ts", "import": "./dist/index.js"}}
```

tsx 把 `.ts` 编成 **CJS** 交给 Node，于是走 `require` 解析。根路径 `.` 有 `main: ./dist/index.js`
兜底能过；**深子路径（`./asset/pg`、无导出表的整包）没有兜底** ⇒ 报错。

判据必须分两条命令验，**`import` 能过不等于 tsx 能过**：

```
node -e "import('@openmaic/dsl')"    → OK 78                    ← ESM 能过
node -e "require('@openmaic/dsl')"   → ERR_PACKAGE_PATH_NOT_EXPORTED  ← CJS 过不去
```

**修法（比 esbuild 干净得多）**：给 tsconfig 加一条 `paths` 映射直指 `dist/index.js`：

```json
{"compilerOptions": {"paths": {"@openmaic/dsl": ["<绝对>/packages/@openmaic/dsl/dist/index.js"]}}}
```

★ **`baseUrl` 与 `paths` 必须都是绝对路径**。三个变体对照实验（配置放 C 盘还能不能跑）：
`A_abs_base_abs_paths` 过 / `B_abs_base_rel_paths` **只在配置躺在仓内时**过 / `C_noextends_abs` 过。
相对值相对的是 **tsconfig 文件自己所在目录**，配置一挪就全指错（实测报 `Cannot find package '@/lib'`）。
⇒ 宿主 `lib/index.js` 的 `bridgeTsConfig()` **运行时生成**到 `os.tmpdir()`，`extends` 仓根 tsconfig +
绝对 `baseUrl`/`paths`；写失败退回仓根那份（attempt-fold 类命令会失败，别的诊断照旧）。

**走过但弃用的路**：esbuild 全打包（10386526 B）能加载，但进程**卡住 >60s 不退出**
（`packages/@openmaic/storage/dist/server/reference.js` 的加载期副作用）。仅记作备用。

## 1.21 审查两件接进 DSH：**模型在宿主、判据在仓里**，靠一条行协议

`openmaic_review_course` / `openmaic_page_review` 是唯一需要**真调模型**的两个工具。
`aiCall` 这一根线由宿主提供，其余全部原样复用仓内实现。

### 1.21.1 为什么不重写判据
`lib/server/agent-runtime/review-tools.ts` 里三段东西抄一遍就会走样，而且错的后果是
**模型照着错建议去改学习者课件**：
- **分段预算**（`:354` 的 `slice(0, maxPages)` 与字符预算 `if (pages.length > 0 && used + page.text.length > budget) break;` 是两条不同的截断）
- **全课首次出现索引**（`firstOrder` / `firstSeen` / `renderedByOrder`，段内已渲过的页不重渲 —— jsdom 渲 26 个 interactive 页很贵）
- **越界缺口机器复核**（`outOfScopeGapClaims()`，`:236`）

⇒ 桥 `lib/diag.mts` 直接 `buildCourseReviewTool({ loadScenes, aiCall, … }).execute(...)` 与
`reviewPageWithContext({scenes, order}, {aiCall, …})`，只把 `aiCall` 换成「问宿主」。

### 1.21.2 ★ 行协议：spawn 保 stdin、stdout 走两种行
一次审查是分钟级；`spawnSync` 会把 DSH 事件循环整个冻住。而模型只在宿主进程里。所以：

| 方向 | 内容 |
|---|---|
| 宿主 → 桥（第一行） | 命令输入 JSON |
| 桥 → 宿主 | `{"__rpc":"llm","system":…,"user":…}` + **换行** |
| 宿主 → 桥 | `{"__rpc":"llm-result","text":…}` + **换行** |
| 桥 → 宿主（收尾） | 最终结果 JSON，**不带换行** |

宿主侧的判据只有一条：**stdout 缓冲里按换行切，切出完整行的都是 RPC，剩下那个尾巴才是结果**。
`spawn` 的 `maxBuffer` / `timeout` 选项**对 spawn 不适用**（那是 spawnSync 的），要自己累加 +
自己数超时（上限 64 MB / 15 分钟）。

### 1.21.3 ★ 桥写完必须自己退：否则宿主永远等不到 close
现象：真库审查跑满 60 秒无输出。根因：桥在 stdin 上挂了 `data` / `end` 监听器，而宿主的
`spawn` **保持 stdin 打开**（要给审查回模型结果）⇒ 事件循环永不退出 ⇒ 子进程不结束 ⇒
宿主的 `child.on('close')` 不触发。

修法（`main()` 尾巴，三件事缺一不可）：
```js
try { process.stdin.pause(); process.stdin.destroy(); } catch {}
process.stdout.write(JSON.stringify(output), () => { process.exit(0); });
```
① 显式 end 掉 stdin ② 在 `write` 的**回调**里再 exit（`write` 是异步的，紧接 exit 会截断）
③ **不靠自然退出**（桥挂着 tsconfig / jsdom 的句柄）。

### 1.21.4 ★ review 不吞模型错误，桥要吞
`review-tools.ts:470` 直调 `aiCall`，模型挂了就抛 —— **这是故意的**（审查是只读活，挂了就该明说）。
但桥必须把它变成 JSON，否则宿主只看到「退出码 1」和一段 stderr。`try/catch` 之后回

### 1.21.5 模型由 DSH 给，不复用 OpenMAIC 的授权链

```js

for await (const chunk of ctx.llm.stream({ ...route, system, messages })) { … }
```

★ `ctx.llm.stream` 是**唯一受支持**的调模型路径（`dsh-llm/README.md` 原文 "it is the only

## 1.24 画布编辑接进 DSH（F18）：手势在面板、写入走 `/patch` 一条路

### 一、为什么手势在面板、写入在宿主

`patchStage`（`lib/index.js:722`）本来就吃 `ops`（add / remove / move / resize / text / canvasField 六种）+ `dryRun` + `diff.counts` 七桶 —— **判据一件都不用重写**。F18 缺的只是面板侧的拖拽 UI 和一条能把它接到 `patchStage` 的缝。

### 二、坐标换算（错一次会「高分屏拖一倍跑两倍」）

`packages/@openmaic/renderer/src/SlideElement.tsx:181-184` 的 `transform: translate3d(${dragOffset.x}px, …)` ⇒ **`dragOffset` 单位是缩放后的 CSS 像素**。所以指针位移必须除以 `scale` 才是画布坐标：

```js
const dx = (ev.clientX - d.x0) / d.scale;   // 不除就错
```

输出用百分比，窗口宽度变了不用重算：`pctX = (v / vw) * 100 + '%'`、`pctY = (v / (vw * vr)) * 100 + '%'`（`vw = canvas.viewportSize || 1000`、`vr = canvas.viewportRatio || 0.5625`）。

### 三、★ 第一版三个假绿：`SEAM` 在这个文件里根本不存在

新代码写了 `fetch(SEAM + '/patch')`，而 `lib/client.src.js` 里其它 fetch 全用 `const ROUTE = '/dsh-openmaic'`（`:15`）。`ReferenceError: SEAM is not defined` **被 try/catch 吞成 `patchMsg`** ⇒ 界面无红、`patches.length` 恒 0。

### 四、★ CAS 基准必须取整份 `data`，不能用 `page`

`/page` 只回**六个精选字段**（`id/stageId/type/title/order/content/actions`，`lib/db.mjs:266-284`），而 CAS 比对的是 `document_scenes.data` **整行**：

```sql
update document_scenes set data = $1::jsonb

```

拿 `page` 当基准 ⇒ `data` 少了 `stageId/createdAt/updatedAt/outlineId` 等键 ⇒ **稳定报**「这一页在你编辑期间被别人改过了（CAS 不成立），重新读一遍再改」。必须用 `db.mjs raw`（`:259`，注释逐字写着「B1 写回要用整份 data 当 CAS 基准，page 只回精选字段（会丢 stageId 等），所以单开一条」）。`patchStage` 本身用的是 `raw`，是我写的 E2E 一开始用错了。

### 五、★ JSONB 会重排键顺序 ⇒ 「逐字节还原」要先规范化

`jsonb` 存的是解析后的值不是原文，读回来键序与写入时不同。所以：

- **不能**直接 `JSON.stringify(before) === JSON.stringify(after)`；
- 要先按 key 递归排序再序列化（`sortKeys` + `canon`）；
- 或换一个与键序无关的指纹。

还原的独立复核：还原前后两次 `raw` 读取的序列化串**完全相同**（`md5 7dc2de0ef089` / 3736 B，连读两次也相同）⇒ 真·字节级还原。

## 2.1 行高只有一个来源：渲染器写进 DOM，检查器读同一个数

- **现象**：检查器报"文字装不下"，真渲染却装得下。
- **真因**：同一个常数写在**两个地方**（渲染器 class 里的 `leading-[1.5]`、检查器里的字面量 `1.6`）。库里绝大多数 text 元素**没有** `lineHeight` 字段 ⇒ 全部走回落值 ⇒ 常数错了不是"个别页面错"，是**这一整批结论错**。

TEXT_LINE_HEIGHT`、`padding: ${TEXT_PADDING_PX}px` **显式写进 DOM**，class 里的 `leading-[1.5]` / `p-[10px]` 删掉；`lib/quiz/layout-check.ts` 直接 import。判据 `tests/components/slide-renderer/text-line-height-pin.test.ts`（6 条）要求渲染 DOM 与检查器回落值同数、且渲染器里不许再出现行高字面量。

## 2.3 「是不是我改坏的」= 改前/改后差集（纯算术，不用人眼）

- **现象**：学习者原话「新增两处盒子高度不足……都是既有问题，我的改动是等长的」。
- **真因**：不是判据错，是工具**没把"改前"记住** —— `patch_stage` 只在写完**之后**算一遍。
- **修法/判据**（`a39adee`）：`patch_stage` 把改动前那一页（`resolved.scene`）一起传进诊断。三部件：
  - `layoutFindingKey()` = 一条发现的**身份** = `code` + 元素下标（**不是 message** —— message 里带估算数字，改一个字就变）。
  - `layoutDelta(before, after)` 纯函数 ⇒ `{ added, removed, kept }`。
  - `formatLayoutDelta()` 人话：没变 ⇒「这次改动**没有引入新的问题**，改前就有 N 处，**不是你这次改出来的**」；有变 ⇒「新引入了 N 处」/「✓ 修掉了 N 处」。
- **读数原文**：`generate_scene` 写新页 ⇒ 不给 `previousScene` ⇒ `layoutDeltaText` 是**空串**（判据钉了这条）。判据 `tests/quiz/layout-check.test.ts` +7 条、`scene-diagnostics-density.test.ts` +3 条，**6 道变异全咬**（身份改用 message / 不带下标 / kept 当 added / removed 恒空 / 既有问题不改口 / 不给 previousScene 也算差集）。
- ★ 通用形状：凡"这个缺陷是不是刚引入的"，都该记住改前那一版再作差。同形状适用：字数带、覆盖缺口、计划依赖。

## 2.4 量尺本身也是第三个来源

- **现象**：`measure-slide-fit.mjs` 量的不是应用画出来的东西。
- **真因**：它自带了**一份**参数且错了两处 —— `padding: hasTextInsets ? 0 : '10px'`（真渲染器**无条件**加内边距，那条分支本部署从来没成立）⇒ 量的盒子比真渲染**宽**；元素没带 `lineHeight` 就什么都不设 ⇒ 浏览器用 `normal`（≈1.25）而不是回落值 **1.5** ⇒ "库值"那一列逐条系统性偏乐观（第 4 页 el11 旧表"余 10px"、真值"**余 4px**"）。

## 2.15 阶段冻结：冻结的是"阶段的准入"，不是"计划内容"

- 用户先说「边做边想也挺好的」，后说「阶段冻结我觉得也要」——**不矛盾**。合起来：**内容**随时改 ＋ **结构**不许无纪变更；计划**不进**系统提示词（按需 `read_stage_outline` 读）＋ **每一页在计划里必须有条目**；计划**可以**改，但要**显式改、且留痕**。

- ★ **修订次数就是"边做边想"的计量器**：0 = 一次想清楚，大 = 边做边想但每次都留了痕。

## 2.17 「计划工具容量只有 47 条」是模型对着我们的 bug 做规划

这是四层链条，**没有任何一层是"容量"**。按发现顺序：

**第一层：`add` 按 order 静默覆盖。**
- 现象：51 页 / 计划 47 条，缺 order = 37,40,46,47；agent 原话「补一次、洞往后挪一格」。
- 真因：`upsertOutlineEntry` 按 **order** 认身份 ⇒ 往已占用 order 写就是覆盖另一页且不报错。
- 修法：`add` 先做冲突检查 —— 同 order 已有**标题不同**的条目就整批拒绝、一个字不写盘；同标题重写放行、往空 order 写放行。
- 判据：`plan-freeze-add-clobber.test.ts` 4 条 + 变异。
- ★ 弯路：先改 `renumberCourseOrders` 里 `flatMap(… => [])` 结果既有判据变红（「renumbers scenes and outline entries together for reorder and **delete**」）⇒ 完整撤回。**教训：改看起来像 bug 的丢弃逻辑前，先看有没有判据钉着它的语义。**

**第二层：同一身份出现两次 ⇒ "每补一条就挤掉一条，等量交换"。**
- 现象：agent 报「现在 51 条 / 56 页，缺 7,8,9,12,20,52，另有一条 order 15 重复；每补一条就挤掉一条」。
- 真因：`upsertOutlineEntry` 用 `findIndex` 找第一条同 order 替换 ⇒ 同 order 两份时第二条永远碰不到 ⇒ 总数永远不变。
- 修法：① 写时同 order 只保留刚写进去那条；② `plan_freeze status` 直接报出缺号与重号。
- ★ 陷阱：`sameEntry` 的提前返回会绕过去重（内容一样就 `return changed:false`）——"无需修改"的前提要加上"那个 order 上只有一条"。
- **通则**：**"容量不足"先怀疑"同一身份出现两次"。**

**第三层：id 从 order 推出来，页号被平移过 ⇒ id 与 order 脱钩。**
- 现象：用户报「补进 9 条、同时丢掉 9 条，总数恒为 50」。代码里没有任何截断（grep 无命中）。
- 真因：新计划里 `(12,'p5') (18,'p12') (25,'p18') (28,'p21')` 大面积错位，而 `upsertOutlineEntry` **先按 id 认身份** ⇒ 给 order 21 写 `id: p21` 会找到坐在 order 28 上的那条并把它搬走 ⇒ 每次写入都在搬家。
- 读数原文：`backfill` 自称"补了 9 条、原有 50 条一个字没动"，实际 **50 → 53**（进来 9、被偷走 6：21,26,29,31,37,41）。
- 修法：**身份键由调用方选** —— `upsertOutlineEntry(…, { matchBy: 'id' | 'order' })`，默认 `'id'`；`generate_scene` 的 id 是真身份；`plan_freeze` 的 add/backfill/revise-entries 三处一律 `'order'`。
- ★ 存量错位 id 因此无害，**不需要数据迁移**。

## 2.19 计划落盘：`upsertOutlineEntry()` 的三个刻意决定

## 3.9 ★ 只改标签时，差集曾经报「零改动」而库里字节确实变了

- **现象**（2026-10-30 实测）：`textsJson` 只把 `<strong>` 的边界挪一下 —— 可见文字逐字相同 —— 写库成功、`changes` 报「文字改」，但差集的七个变更桶**全是 0**。调用方看到的是「说要改，又说没改」。
- **真因**：`elementText()` 先 `stripHtml()` 再比，标签差异被抹平；`strip()` 又把 `content` 剥掉，于是 markup-only 的改动在七个桶里都无处落脚。这不是显示问题 —— 库里的字节**真的变了**（`4007 → 4008`），所以「桶全 0」是一种**假绿灯**。
- **修法**（插件仓 `9445163`，三处）：① 新增 `elementMarkup()` 返回未剥标签的原文；② 新增 `markupChanged` 桶 —— `elementText` 相同但 `elementMarkup` 不同才进，真改字/真改样式/逐字节相同三种情形全部不受影响；③ 七个变更桶全 0 时，`dryRun` 与非 `dryRun` **两条路径都追加 `note`**：「差集看不见这次改动，但库里字节会变」。
- **判据（五向，差集纯函数直跑）**：markup-only → `textChanged 0, markupChanged 1` ✅ / 真改字 → `textChanged 1, markupChanged 0` ✅ / 真改样式（fontSize 48）→ `restyled 1` ✅ / 逐字节相同 → 全 0 且**无** note ✅ / 只多一个空 `<span>` → `markupChanged 1` ✅。

## 5.6 反斜杠会被 heredoc 吃掉

- **现象**：写进脚本的正则少了一个 `\`，跑出来行为诡异。
- **真因**：`bash -c` + `<<'PYEOF'` 的引号 heredoc 里，`\\` 会折成 `\`（当次会话被咬 **6 次**）。更精确的规律：
  - python 字符串里 `\b \n \r \t \f \v \a \0` 是**合法转义** ⇒ 被吃掉（`\b` 变退格 0x08，正则里没词边界）；
  - `\s \w \d` **不合法** ⇒ 原样保留（只给 `SyntaxWarning`）。
- **修法/判据**：写含反斜杠的正则**一律用占位符**或 `edit` 工具，不要过 heredoc。
- ★ 连带的读文件坑：`pathlib.read_text()` 的通用换行会把裸 `\r` 翻成 `\n` ⇒ **要数行尾就用 `read_bytes()`**。

## 6.7 `browse_page` 是**间歇性**超时，不是「所有外网都被拦」（2026-10-30 实测，推翻旧说法）

- ★ **但同一 URL 立刻重试就 `ok`**：连跑三次 `https://ocw.mit.edu/about/` ⇒ `ok len=8569` / `ok len=8569` / `FAIL Timeout`。**同一个域名、同一台机器、同一分钟，成败交替。**
