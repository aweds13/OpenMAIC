| 结论 | 依据 |

| **批量下载在课程标签页工具栏**（不是行内菜单）：勾选多门课 → **一个 ZIP** | 浏览器会拦截连续多次自动下载，N 个文件必须打成一个包 |

| **★ 计划从来没落盘过**（T1 修的就是这个）—— brief 生成完就扔 | 2026-10-07 实测**基线**：本部署 **7 门课、计划条目全是 0**（`document_outlines.data->'outlines'` 长度为 0，`producer` 全 `server-job`）。也就是说这个部署**从来没有一条 brief 落盘**。后果是静默的、而且不止一处：<br>· `read_stage_outline` 显示的 description 退化成**页面标题**（`mergeStageOutline` 配不到计划条目时用 `scene.title` 兜底）—— agent 自己都看不到当初的要求；<br>· ⚠️ **更正一条我写错的结论**：我曾写「`edit_deck` 的 `shiftCourseOrders` / `renumberCourseOrders` 在
  `outlines.length === 0` 时直接原样返回 ⇒ 这两条重排逻辑是死代码」。**错了。** 实测代码
  （`course-edit/tools.ts:65-68` 与 `:84-85`）：**场景的 `order` 是无条件重排的**
  （`scenes.map(...)` 直接跑），`if (!outline?.outlines?.length) return` **只跳过"同步 outline 条目"那半** ——
  而计划为空时本来就没有条目要同步。**所以给旧课拆页/插页/删页都能正常工作，不受"计划为空"影响。**
  这条错误的代价是：它会让人以为"必须先给旧课补计划才能改结构"，从而白做一层前置工作。<br>· 「练习只能考教过的」那类依赖检查（T3）**没有可校验的计划**。<br>**修法**：`generate_scene` 写页之后，用 `upsertOutlineEntry()` 把同一条 `SceneOutline`（就是喂给内容生成器的那一条）按 **outlineId → order** upsert 进计划。三个刻意的决定：① **替换而不是追加**（重生成很常见，追加会堆出同 order 的僵尸条目，让 order 兜底匹配配到错的那条）；② 写 outline 只能走**全量** `saveDocument`（存储层没有增量 API），所以 `changed: false` 时**跳过整篇保存**；③ **不动 `generationComplete`** —— agent 造的课出生就是 `true`，而在该标志下 `mergeStageOutline` 只显示已落盘的页，这正是我们要的（否则课程列表会凭空多出不存在页）。<br>写 scene 与写 outline 是两次写，中间崩掉的结果就是**今天的行为**（brief 没落盘、页面还在）⇒ 纯改善，无新的坏状态。details 里有 `outlinePersisted` 供 SQL 读。<br>**验证要看**：真跑一次 `generate_scene`，然后 `SELECT jsonb_array_length(data->'outlines') FROM document_outlines` 应 > 0。回归 pin：`tests/agent-runtime/course-outline-write.test.ts` |
| **计划期依赖校验**（`lib/quiz/plan-check.ts`，T3）：只给「补」和「挪」的诊断 | 在 `generate_scene` 写下计划那一刻跑（比 T2 更早、更便宜），两半共用同一把尺子（`contentChunks`）。三条判据：**超前引用**（某页要考的东西，讲它的页排在它后面）、**无归属**（没有任何讲解页讲过它）、**预算**（一页引入太多新概念 ⇒ 拆页）。★ **每条的输出只允许「补」和「挪」**，不许删题 / 砍概念 / 合并页 —— 门禁一旦允许删就会变成棘轮，讲解页越薄它把课程压得越薄（用户当面纠正过）。<br>**两道闸都是实测逼出来的**：① 自检页**只看 brief + keyPoints，不看标题** —— 标题是标签（「小测」），算进去会把它报成「没讲就考」；讲解页仍看标题（标题本身在教词）。② **新颖 + 重复 ≥2 页**（与 T2 同款判据）：`考封装：private 字段怎么读` 里的「怎么读」只出现在一页 ⇒ 是口气话不是概念。另外判据按**块包含**（「考封装」含已教的「封装」）。<br>⚠️ **精度还没被真实数据验证过**：`conceptsPerPage`（预算规则）**默认关闭**，因为**内容块 ≠ 概念**（实测「封装 private 字段 getter setter」切出 5 个块却只是 1 个概念），而标定只能拿真实计划数据 —— T1 之前这个部署的计划**永远是空的**。**第一次真跑之后回看 `planIssueCount`，再决定要不要收紧。** 回归 pin：`tests/quiz/plan-check.test.ts`（15 条） |
