## 六、上线口径（切主树时踩到的三件，都是**必须**做的）

1. **`pnpm install` 之后必须再跑一次 `pnpm run build:packages`**。install 的 `postinstall` 里包是并跑的，实测
   `@openmaic/renderer` 在 `@openmaic/dsl` 之前 build（日志 `@rollup/plugin-typescript TS2307: Cannot find
   module '@openmaic/dsl'`）⇒ renderer 的 `dist/*.d.ts` 是残的，`tsc` 报假错
   （`Module '"@openmaic/renderer"' has no exported member 'SlideEffects'`）。按依赖序重跑
   `build:packages` 之后 `tsc --noEmit` EXIT=0。（`dist/` 与 `node_modules/` 都是 gitignore 的。）
2. **`.env.local` 里的 `MODEL_ROUTES` 必须注释/删掉**。1.2.0 的 server-first 模型配置不再接受它：
   只要它存在且没有 `openmaic.yml`，启动即拒 ——
   `[boot] Invalid server configuration; the server will not start: MODEL_ROUTES does not carry over to the
   model configuration: write the per-stage models as slots in openmaic.yml (or the file named by
   OPENMAIC_CONFIG) and remove MODEL_ROUTES`（`lib/server/model-config/deployment-layer.ts:42` `LegacyRoutesError`）。
   等价物是 `openmaic.yml` 的 `slots:`；本部署没建 yml ⇒ 走 legacy 翻译，`DEFAULT_MODEL=deepseek:deepseek-v4-flash`
   仍生效，`agent` 槽默认继承 `llm` 槽（行为不变）。`.env.local` 备份在
   `_tools/openmaic/diagnostics/env-local-备份-2026-10-17-合上游前.txt`。
3. **`openmaic.yml` 一旦建了就是整体替换**：`deployment-layer.ts` 头注释写明"文件存在就用它，不再翻译 env 的
   providers / DEFAULT_MODEL / MODEL_FALLBACK" ⇒ 想用 yml 必须把 providers 全写进去，否则模型全掉。
   现在**刻意不建**。

## 七、生产构建 vs dev：首屏慢在哪里（2026-10-17 实测）

结论先行：**「点进去卡」是 dev 的一半，不是内核的一半**。同一台机器、同一个 URL、同一版代码，
Edge（`channel:'msedge'`，1440×900，每个 URL 3 次取中位）：

| 指标 | dev（`next dev`） | 生产（`.next/standalone/server.js`） |
|---|---|---|
| `/workspace` TTFB | 157 ms | **55 ms** |
| `/workspace` DCL | 367 ms | **241 ms** |
| `/classroom/<id>?page=1` TTFB | 160 ms | **33 ms** |
| `/classroom/<id>?page=1` 幻灯片正文出现 | **3921 ms** | **1534 ms** |
| 请求数 | 120 / 126 | 87 / 88 |
| 传输字节 | 331 KB / 1367 KB | 330 KB / 1367 KB |

（字节几乎一样 ⇒ 慢的不是"内容变多"，是 dev 未压缩的 chunk 与按需编译。冷启动那一下更明显：
不带 `?page=1` 首次访问 `/classroom/<id>`，dev 实测 **27.8 s**，warm 后 0.13–0.18 s。）

复现：`node _tools/openmaic/diagnostics/measure-page-timing.mjs dev|prod <url> [url…]`
（`D:\文档\jelly_ware\_tools\openmaic\diagnostics\measure-page-timing.mjs`；本机没装 playwright 的 chromium，用真 Edge）。

### 怎么跑生产构建（三步，缺一不可）

```bash
pnpm build                                            # 1. 产物在 .next/standalone
mkdir -p .next/standalone/.next .next/standalone/public
cp -r .next/static .next/standalone/.next/static       # 2. 静态资源 standalone 不带，要自己拷
cp -r public/. .next/standalone/public/
cp .env.local .next/standalone/.env.local              # 3. ★ standalone 只从**自己的目录**读 .env*
cd .next/standalone && PORT=3000 node server.js
```

★ 第 3 步不做的后果（实测原文）：`[boot] Invalid server configuration; the server will not start:
DATABASE_URL is not set.` —— 它不会去读仓库根的 `.env.local`。
★ 生产模式起在 3000 时，`start_all.cmd` 仍然可用：已监听的端口只报告、不动，然后打开工作台。
★ 改代码要重启（生产不打补丁）；日常改代码换回 `npm run dev`（先停 3000）。
★ 首屏 1.5 s 里剩下的主要是课程那一坨数据与渲染本身，要再快就得改数据加载（另立项，不在合并范围）。
