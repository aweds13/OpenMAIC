## 1 一句话结论

**一期只做"行为面收敛"，不动数据模型**：把今天 15 个仓内工具 + 3 个插件工具收敛成 **5 个工具的单一语义面**（无 `scope`、无删除、无 `prepare`），把读侧围栏/分页/revision/全文阈值做成**唯一一份实现**，把三套抽取 worker 收敛成**一套 owner token 链**，把插件三件收敛成**一个入口**，全部落在现有 PG 表上（`owner_material` 等）、DDL 一行不改。

二期才动 DDL（v6：废列、`kind` 收紧、`asset_id` NOT NULL）与目录一次性导入。三期才上向量兜底与 pika 合并检索。

**理由**：02 的 15 条冲突里，C5/C10/C11/C13/C14 五条是"文案/校验/形状"（R10 已指出），C1/C2/C6/C7/C15 五条是"参数与注册"，**没有一条必须改 DDL 才能修**；而 DDL 迁移（v6）一旦先做，工具面改动会被迫与迁移绑在一起，出问题无法二分定位。

## 3 目标架构（四层 + 一个插件入口）

```
┌ 工具层（模型看得见）────────────────────────────────────────┐
│ 5 个工具：list_materials / read_material / search_materials   │
│           add_materials / organize_materials                  │
│ 唯一实现：lib/server/agent-runtime/material-tools.ts（重写）   │
└───────────────┬───────────────────────────────────────────────┘
                │ 只依赖 service 接口，不 import 持久层
┌ 服务层（业务判据）───────────────────────────────────────────┐
│ MaterialAgentService：list/read/search/add/organize           │
│   ├─ 围栏（untrusted-material.ts，已有）                      │
│   ├─ 分页游标 + revision 计算                                 │
│   ├─ 配额检查（条数/字节）                                    │
│   └─ 查询扩展（material-query-expansion.ts，已有）            │
│ MaterialAdminService：deleteMaterial / deleteMaterialFolder   │
│   └─ 只有 HTTP 路由与 UI 能 import；工具层 import 不到         │
└───────────────┬───────────────────────────────────────────────┘
                │
┌ 持久层（唯一真源）───────────────────────────────────────────┐
│ owner_material / material_folders / agent_session_material_links │
│ asset_blobs / asset_entries / asset_root_refs（池）            │
│ 抽取：owner token 链（claim / heartbeat / settle）             │
└───────────────────────────────────────────────────────────────┘

插件侧：① 一个入口 openmaic_material（action 与上面 5 个 1:1）
        ② 走桥直调同一份 execute()，不重写判据
        ③ 绝不走 HTTP（HTTP 授权靠页面 cookie，插件只有 OWNER_ID）
```

**为什么服务层要拆两个**：R8 的结构性风险——今天"模型删不掉材料"不是靠权限，是靠**工具面上根本没有 delete 代码**。只要工具层与 HTTP 路由共用一个 service，一次重构就可能把 delete 漏给模型。拆开后，工具层的 import 语句本身就是判据（`MaterialAdminService` 不出现在 `material-tools.ts` 的 import 里），可以用一条静态测试钉住。

## 4 工具面：最终 5 个

公共约定（沿用 02 §4.0，一处改动：**没有 `scope`**）：

1. owner 永不出现——不在参数、返回、错误码里。
2. 没有 `scope` 参数；每行返回 `source: 'course' | 'conversation'`。
3. 没有删除动词。
4. 分页：请求 `{ before?, limit? }`（limit 1..200，默认 50）→ 响应 `{ nextBefore? }`；游标失效回空页 + `details.staleCursor: true`。
5. revision 不透明（`session:<rowId>` / `sha256:<16hex>`），模型只回传不解析；`offset > 0` 必传。
6. 错误一律 `isError: true` + `details.status`（17 条枚举），**不抛异常**；状态类（`revision_changed` / `unsupported_kind` / `extraction_required` / `extraction_failed`）是 `isError: false`。
7. 材料正文一律围栏（`untrustedMaterialBlock`）。
8. 写工具必须带 `changed: boolean` + 受影响 id 列表。

### 4.1 `list_materials`

```
list_materials({ query?, folderId?, kind?, source?, before?, limit? })
```

| 参数 | 类型 | 约束 |
|---|---|---|
| `query` | string | 1..200，名字与 mime 的**大小写不敏感字面**匹配 |
| `folderId` | string | `'top-level'` = 不在任何文件夹；省略 = 不按文件夹过滤 |
| `kind` | enum | `source`\|`derived`\|`web`\|`image`\|`topic`；省略 = 全部 |
| `source` | enum | `course`\|`conversation`；省略 = 两者合并 |
| `before` | string | 上一页 `nextBefore`，必须带同样过滤条件 |
| `limit` | int | 1..200，默认 50 |

返回：

```json
{
  "materials": [ { "materialId": "mat_…", "kind": "source", "title": "…",
                   "mime": "application/pdf", "bytes": 812345,
                   "folder": { "folderId": "fld_…", "name": "第三章" },
                   "source": "course", "attached": true, "derivedFrom": null,
                   "extraction": { "status": "done", "statusLabel": "Parsed" },
                   "textChars": 18234, "createdAt": "…" } ],
  "folders": [ { "folderId": "fld_…", "name": "第三章", "count": 7 } ],
  "nextBefore": "mat_…", "staleCursor": false, "truncated": false
}
```

★ `folders` 是**全量**（≤ `FOLDER_COUNT_LIMIT = 50`），不接受 `before`——它是"这一级组织在哪"，不是列表数据。

★ 一期 `kind` 枚举必须与今天一致：`OWNER_MATERIAL_KINDS = ['source','web','image']`（`lib/persistence/owner-materials.ts:56`）+ fork 的 `topic`。`derived` 不是真 kind，是"有 `derived_from` 或者来自会话副本"的集合——**一期不引入 `derived` 这个 kind 值**，改成 `kind: 'image' | 'web' | 'source' | 'topic'`，另给布尔 `isDerived`。理由：`derived_from` 是列不是 kind（`:205`），把两者混成一个枚举会让 DDL 二期改不动。

### 4.2 `read_material`

```
read_material({ materialId, offset?, revision? })
```

`materialId` 同时接受三种：材料 id、`topic:<slug>`（主题笔记）。**不接受 `ast_`**（池资产）——那是 `use_material_media` 的事，一期不做（D9）。

返回两段 content：围栏内正文（窗口 = `materialFulltextThresholdChars()`，默认 30000）+ 围栏外可信页脚（分页指引）。

```
A readable source comes back in one piece up to about 30000 characters (…).
Characters 30000-60000 of 213450 of material mat_…, revision "sha256:…".
Next page: read_material with offset 60000 and revision "sha256:…".
```

`details: { materialId, revision, offset, totalChars, nextOffset?, kind, source, title, textFrom: 'extraction'|'native'|'topic' }`

### 4.3 `search_materials`

```
search_materials({ query, kind?, source?, before?, limit? })
```

- `query` 1..200；走 `expandMaterialQuery`（已有）做查询扩展，**扩展失败只用原词**（永不抛）。
- 返回 `{ hits: [{ materialId, title, source, kind, matchedTerm, snippet, offset }], expandedTerms?, expansionReason?, nextBefore? }`
- `snippet` **逐个围栏**（不是整块 `JSON.stringify`）——这是 05 §3.5 #3 指出的第 3 处漏围栏。
- 全文直读判定：命中的材料同一次调用里若 `textChars ≤ 阈值`，`hits[].fullText` 直接带全文（已在围栏内）；否则只给 snippet + `offset`，提示用 `read_material`。

### 4.4 `add_materials`

一期只做**知识侧**的两件事（文件上传仍由人在 UI 上做，02 §4.10）：

```
add_materials({ target: 'note', topic, mode: 'append'|'replace', content, expectedRevision?, clientToken? })
```

- `mode: 'replace'` 时 `expectedRevision` 必填（C6 的修法）；`append` 不需要，但返回 `appendedChars`。
- `clientToken` 是幂等键（C14 的修法）：同 token 重复调用回同一结果、不二次追加。
- 无删除：删主题文件是人的动作（文件系统层面）。
- 上限沿用 `MAX_WRITE_CHARS = 200_000`（`lib/server/agent-runtime/materials-library.ts:55`）。

★ `import_pptx` **不并入**（02 R4 判据：它改课件页，不改材料库）。`fetch_url` 也不并入。

### 4.5 `organize_materials`

```
organize_materials({ action: 'create_folder'|'rename_folder'|'move'|'rename', … })
```

| action | 参数 | 返回 |
|---|---|---|
| `create_folder` | `name` | `{ changed, folderId }` |
| `rename_folder` | `folderId, name` | `{ changed, folderId }` |
| `move` | `materialIds: string[]`（≤ `MAX_MOVE_MATERIALS = 100`）, `folderId`（`'top-level'` 可） | `{ changed, moved: string[] }` |
| `rename` | `materialId, name` | `{ changed, materialId }` |

★ `list_folders` 不在这里（见 §4.1）。

★ 名字长度上限**收敛成一个口径**（C10 的修法）：
- 文件夹：显示宽度 ≤ 40（`FOLDER_NAME_MAX_WIDTH`，`lib/utils/folder-name-validation.ts:12`），文案改成「最多 40 个半角 / 20 个全角字符」，schema 里**删掉** `maxLength: 80` 改用运行时校验（`material-library-tools.ts:36`/`:40`）。
- 材料名：`MATERIAL_NAME_MAX_LENGTH = 255`（`lib/persistence/material-library.ts:83`），schema `maxLength: 255`（一致，今天也是 255，只是文案没同步）。

## 8 插件侧：三个入口收敛成一个

```
openmaic_material({ action: 'list'|'read'|'search'|'add'|'organize', … })
```

- 参数与 §4 的 5 个工具**同名同形**（`action` 只是把工具名挪进参数）。
- 实现：继续走 `runDiag` 桥（`lib/diag.mts`），桥里直调同一份 `execute()`——**不重写判据**（02 §6.3 A+）。
- ★ 必须删掉三处补丁：① `scope` 默认 `'library'`（`lib/diag.mts:1429-1431`）② 自造 sessionId（`:1378-1385`）③ `extract`/`wait` 的 `driveOwnerExtraction` 手驱（`:1418-1425`）——一期没有 `prepare` 动作了。
- `materialIds` 从"逗号分隔字符串"改成 JSON 数组，保留一版兼容。
- 旧三个名字保留一个版本作为 deprecated 转发（`openmaic_materials` / `openmaic_material_ops` / `openmaic_material_folders`），下一版删。
- ★ 绝不走 HTTP：HTTP 授权靠页面 cookie，插件只有 `OWNER_ID`；且 HTTP 侧 DELETE 已存在，插件一旦学会调 HTTP，离删材料只差一个 action 字符串。
