## 1 一句话结论

统一后模型看见 **9 个工具**，都属于材料模块：

**材料面 7 个** —— `list_materials` / `read_material` / `search_materials` / `add_materials` / `prepare_materials` / `organize_materials` / `use_material_media`；
**主题笔记面 2 个** —— `read_material_topic` / `write_material_topic`；
**删除类 0 个** —— 删材料、删文件夹只有人能点（HTTP DELETE），这是 D7 的硬约束，不是配置项。

另外两个今天被算进"材料工具"的（`fetch_url`、`import_pptx`）**不在合并范围**：前者是通用网页读取，后者改的是课件页面而不是材料库（理由见 §7 R4）。

今天模型实际可调用 **15 个**材料相关工具（5 + 5 + 2 + 1 + 1 + 1），加插件侧 3 个共 **18 个**。合并后 15 → 10（9 个材料模块 + `fetch_url` 原样），插件侧 3 → 1。

## 4 统一后的工具面

### 4.0 九条通用约定（对所有工具成立）

1. **owner 永不出现**——不在参数、不在返回值、不在错误码里。
2. **没有 `scope` 参数**。跨会话可见性由返回里每行的 `source` 标出；模型不需要知道"我在哪个 scope"。
3. **没有删除动词**。
4. **分页统一**：请求 `{before?, limit?}`（limit 1..200，默认 50）→ 响应 `{nextBefore?}`。`before` 失效回空页 + `details.staleCursor:true`（今天会话分支是静默空页）。
5. **revision 是不透明字符串**，模型只回传、不解析。格式 `session:<rowId>` / `sha256:<16hex>`。`offset>0` 必传。
6. **错误一律 `isError:true`**，且 `details.status` 是稳定枚举（见 4.3）；`details.message` 是人话（走 copy），`details.guidance` 可选。**不抛异常**。
7. **材料正文一律围栏**（D6）：读侧、搜索片段、主题文件正文，全部走同一个 `fence(text, nonce)`。
8. **每次返回都带 `source`**：`'course'`（库）或 `'conversation'`（会话副本）。
9. **写工具的返回必须能判断"到底改了什么"**：`changed:boolean` + 受影响 id 列表；不做"看起来成功"。

### 4.1 `list_materials`

```
list_materials({ query?, folderId?, kind?, before?, limit? })
```

| 参数 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `query` | string | 否 | 1..200 | 名字与文件类型的**大小写不敏感字面**匹配；不是正则 |
| `folderId` | string | 否 | `'top-level'` 或文件夹 id | 省略 = 不按文件夹过滤；`'top-level'` = 不在任何文件夹 |
| `kind` | string | 否 | `source`\|`derived`\|`web`\|`transcript`\|`topic` | 省略 = 全部；新增（今天只能靠 `kind` 字段自己过滤） |
| `before` | string | 否 | 上一页的 `nextBefore` | 必须带**同样**的过滤条件 |
| `limit` | int | 否 | 1..200，默认 50 | 今天库页硬编码 100、会话 50（`:643`/`:94`），这里统一 |

返回：

```json
{
  "materials": [
    {
      "materialId": "mat_...", "kind": "source|derived|web|transcript|topic",
      "title": "第三章 不动点.pdf", "mime": "application/pdf", "bytes": 812345,
      "folder": { "folderId": "fld_...", "name": "第三章" },
      "source": "course", "attached": true, "derivedFrom": null,
      "extraction": { "status": "idle|pending|running|done|failed",
                      "statusLabel": "Stored · not parsed",
                      "reasonCode": "service_unavailable", "reason": "...", "guidance": "..." },
      "textChars": 18234, "createdAt": "2026-11-05T12:00:00.000Z"
    }
  ],
  "nextBefore": "mat_...", "staleCursor": false
}
```

错误：`invalid_argument`（`limit` 越界、`kind` 不认识）。**不返回** `isError` 的空列表——空就 `materials: []` + 一句人话。

### 4.2 `read_material`

```
read_material({ materialId, offset?, revision? })
```

| 参数 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `materialId` | string | 是 | 来自 `list_materials` | 也接受 `topic` 的 materialId（见 4.8），但不接受 `ast_` |
| `offset` | int | 否 | ≥0 | 字符（code point）偏移 |
| `revision` | string | offset>0 时必填 | 上一页给的 | 变了就拒（见错误码） |

返回（content 两段：围栏内是正文，围栏外是可信页脚）：

```
<untrusted-material-content-3f9a...>
（正文逐字，8000 字符窗口）
</untrusted-material-content-3f9a...>
Characters 8000-16000 of 21345 of material mat_..., revision "sha256:...". Next page: read_material with offset 16000 and revision "sha256:...".
```

details：`{materialId, revision, offset, totalChars, nextOffset?, kind, source, title, textFrom:'extraction'|'native'}`

状态（**非错误**，`isError:false`）：`extraction_required`（未解析，附一句"先 prepare_materials，再读"）、`unsupported_kind`（音视频，指去 `use_material_media`）。
错误：`not_found`、`text_unavailable`、`revision_required`、`revision_changed`、`invalid_argument`。

> 与今天的两处差别：① 不再有 `source_requires_derivative`——源已解析就直接给文本；② `revision_changed` 今天**非错误**（`:792`），统一后算 `isError:false` 但 `details.status` 明确，可与今天兼容。

### 4.3 错误码 enum（全模块唯一一份）

| 码 | 是否 `isError` | 何时 |
|---|---|---|
| `invalid_argument` | ✅ | 参数形状/范围/枚举不对（含今天抛异常的 `:854`、`:998`） |
| `not_found` | ✅ | id 不存在 / 不属于这个 owner（不区分"别人的"与"没有的"） |
| `text_unavailable` | ✅ | 有行无文本资产 |
| `revision_required` | ✅ | `offset>0` 没给 `revision` |
| `revision_changed` | ❌（状态） | 给了旧 `revision`，正文已变（`:792` 今天也是非错误） |
| `unsupported_kind` | ❌（状态） | 音视频等不可作文本读（`:1197`） |
| `extraction_required` | ❌（状态） | 未解析（`:543`） |
| `extraction_failed` | ❌（状态） | 解析失败，`reasonCode`/`reason`/`guidance` 三个字段跟着来 |
| `invalid_name` | ✅ | 空名/超长/非法字符 |
| `name_taken` | ✅ | 同名（忽略大小写）已存在 |
| `folder_not_found` | ✅ | 目标文件夹不存在（`:235`） |
| `not_movable` | ✅ | 派生物单独移动（`:258` 段） |
| `too_many` | ✅ | 一次超过 100 个（`MAX_MOVE_MATERIALS`，`material-library.ts:86`） |
| `media_unsupported` | ✅ | mime 不是 image/video/audio（`material-media.ts:85` 段） |
| `media_storage_full` | ✅ | 副本放不下（`details.status:'storage-full'`） |
| `not_configured` | ✅ | **只在已注册却真的没配好时**出现（正常路径靠"不注册"避免，见 C15） |
| `path_outside_library` | ✅ | `add_materials` 的 `path` 不在允许目录内 |
| `too_large` | ✅ | 单次写入超上限（今天 200,000 字符，`materials-library.ts:54`） |
| `stale_cursor` | ❌（标志） | 分页游标失效（配合 `nextBefore` 为空） |

### 4.4 `search_materials`

```
search_materials({ query, materialId?, kind?, before?, limit? })
```

| 参数 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `query` | string | 是 | 1..200 | 字面、大小写不敏感；不支持正则（与今天一致，`:823` 描述） |
| `materialId` | string | 否 | 单个材料 id | 限定范围 |
| `kind` | string | 否 | 同 `list_materials` | 省略 = 可搜的全部（源的材料 + 主题文件，C12） |
| `before` / `limit` | — | 否 | 同 4.0 | 命中分页（今天**没有**分页，只有 30 条硬上限） |

返回：`{query, mode:'literal'|'hybrid', degraded?:true, scannedChars, truncated, hits[], nextBefore?}`
每条 hit：`{materialId, revision, start, end, snippetStart, snippetEnd, snippet}`（`snippet` 在围栏内）。

保留今天的预算语义（100ms CPU / 5s 墙钟 / 1M 字符），但**预算耗尽要能续**：回 `truncated:true` + `resumeBefore`（今天只有一句"results may be incomplete"）。

错误：`invalid_argument`（今天抛，见 C7）。

### 4.5 `add_materials`

```
add_materials({ source: {kind:'path'|'dir'|'url'|'pptx', ...}, folderId?, name? })
```

一个"加"的动词，三种来源（D1：目录是导入通道）：

| `source.kind` | 必填字段 | 行为 | 副作用 |
|---|---|---|---|
| `path` | `path`（绝对路径或相对 `materialsDir`） | 导入单个文件 → 建 `owner_material` 行 + 字节入库 + 启动解析 | 新增行、新增字节、emit `extraction_started` |
| `dir` | `path` | **扫描并显式导入**目录下所有 Markdown（D1 的"导入通道"） | 批量新增行；`skipped[]` 列出已存在/不支持的文件 |
| `url` | `url`, `title?` | 抓网页 → session `web` 材料（**不入库**，与今天 `fetch_url` 的材料化一致） | 新增 session 行 |
| `pptx` | `materialId`, `stageId`, `atOrder?` | 把库里的 .pptx 导入成课件追加页（今天是 `import_pptx`） | **改课件**（见 §7 R4，建议一期**不并入**） |

返回：`{added:[{materialId, kind, title, status, statusLabel}], skipped:[{path, reason}], staged:boolean}`
`staged:true` 表示"已登记，等解析"（对应今天的 `started`，但不要把这个内部字段暴露成 `started: true`——`MATERIAL_USER_WORDING` 明确禁止给用户看这种原始值）。
错误：`invalid_argument`、`path_outside_library`、`folder_not_found`、`too_large`、`too_many`。

> `fetch_url` 保留原样**不并入**：它是通用网页读取（非材料场景也用），并进来会让 `add_materials` 承担"读网页"的语义。

### 4.6 `prepare_materials`

```
prepare_materials({ materialIds?, timeoutSec?, retryFailed? })
```

| 参数 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `materialIds` | string[] | 否 | 1..50，去重 | 省略 = 本会话所有未解析的**源**（今天 session scope 省略即如此，`:1048`）；**不再有"library 必填"这种分支**（因为没 scope 了，C2） |
| `timeoutSec` | int | 否 | 1..300，默认 60 | 与今天一致 |
| `retryFailed` | bool | 否 | 默认 false | `true` 时才重试 `failed`（合并今天的 `extract_material` 的重试语义） |

返回：`{complete, timedOut, materials:[{materialId, status, statusLabel, nextAction?, reasonCode?, reason?, guidance?}]}`
语义合并自两个旧工具：**先启动、再等**；幂等（pending/running/done 不重复启动，`:984` 描述）。

### 4.7 `organize_materials`

```
organize_materials({ action, ... })
```

`action ∈ {list_folders, create_folder, rename_folder, move, rename, attach, detach}`（**没有 delete**）。

| action | 参数 | 返回 | 错误码 |
|---|---|---|---|
| `list_folders` | `query?` | `{status:'listed', folders:[{folderId,name,materialCount}]}` | — |
| `create_folder` | `name`(1..80) | `{status:'created'\|'exists', folder:{folderId,name}, created:boolean}` | `invalid_name`、`too_many` |
| `rename_folder` | `folderId`, `name`(1..80) | `{status:'renamed'\|'unchanged', folder}` | `invalid_name`、`folder_not_found`、`name_taken` |
| `move` | `materialIds`(1..100), `folderId`(`'top-level'` 或 id) | `{status, movedCount, folder, sessionCopyIds?}` | `folder_not_found`、`not_movable`、`too_many` |
| `rename` | `materialId`, `name`(1..255) | `{status:'renamed', materialId, name, sessionCopyIds?}` | `invalid_name`、`not_found`、`unsupported_kind`（派生物） |
| `attach` | `materialIds` | `{attached, alreadyAttached[]}` | `not_found` |
| `detach` | `materialIds` | `{detached}` | `not_found` |

> `attach`/`detach` 是**新增**的：今天"材料进会话"只有隐式路径（`runner.ts:1748` 一进来就把 links 全列进来），模型既不能主动挂也不能主动摘；而 D2 之后"课程库 ↔ 会话"的边界要能被模型表达。

### 4.8 主题笔记面：`read_material_topic` / `write_material_topic`

```
read_material_topic({ topic?, offset?, revision? })
write_material_topic({ topic, content, mode:'append'|'replace', expectedRevision?, clientToken? })
```

| 工具 | 参数 | 返回 |
|---|---|---|
| `read_material_topic` | `topic?`（省略=索引 + 磁盘清单 + 全部主题名）、`offset?`、`revision?` | 无 topic：`{topics:[...], index?:{topic,revision,totalChars}}`；有 topic：围栏正文 + `{topic, revision, offset, totalChars, nextOffset?}` |
| `write_material_topic` | 见上 | `{topic, mode, created:boolean, revision, appendedChars?}` |

- `topic` 仍是 slug（`/^[a-z0-9][a-z0-9-]{0,63}$/`，`materials-library.ts:51`），`'INDEX'` 是保留名（`:42`）。
- **`replace` 已存在文件时必须带 `expectedRevision`**；不带则回 `revision_required`。`append` 不需要（不改前缀），但要回 `appendedChars`。
- 无删除（删主题文件是人的动作，文件系统层面）。
- 上限保持 200,000 字符（`:54`），超了 `too_large`。

### 4.9 `use_material_media`（保留，只减参数）

## 6 与 DSH 插件的关系

### 6.1 现状（实测）

- 3 个工具：`openmaic_materials`（`lib/index.js:1743`，read/write 主题）、`openmaic_material_ops`（`:2752`，list/read/search/extract/wait）、`openmaic_material_folders`（`:2814`，文件夹五件）。
- 实现方式是**子进程桥**：`runDiag` 用 `spawnSync` 跑 `tsx diag.mts <cmd>`（`:359`，timeout 60000），`runDiagAsync` 用 `spawn`（`:114`，extract/wait 给 600000）。桥在 `lib/diag.mts`（1614 行）里**直接 import 仓里的 buildMaterialTools / buildMaterialLibraryTools 并调 `execute()`**（插件注释 `:2730-2745`）。
- 插件对上游做了三处改动：① `scope` 默认 `library`（`diag.mts:1429-1431`）；② 自造 sessionId（`:1378-1385`）；③ `extract`/`wait` 由桥自己 `driveOwnerExtraction` 驱动（`:1418-1425`，因为 `startOwnerMaterialExtractor` 只在 Next 进程里起）。
- 部署副本与源仓**一致**（135289 字节，diff 为空）——即"改了源仓没重装"这类问题现在不存在。

### 6.2 三个选项

| 选项 | 做法 | 代价 |
|---|---|---|
| **A 继续走桥**（现状，只收敛 action） | 3 个工具合成 1 个 `openmaic_material`，参数与 §4 同名同形 | 每次调用 `spawnSync` 冷启动 ~1–2s；仍要在 `diag.mts` 里维护一份"DSH 差异补丁" |
| **B 改调 HTTP 缝** | 用仓里已存在的 `app/api/materials/*`（GET/POST/PATCH/DELETE/move/folders/library） | 授权靠页面会话 cookie，插件没有 cookie；且 DELETE 一学就会（C9） |
| **C 桥改常驻/批处理** | 一个长驻 `diag` 进程吃多命令（NDJSON stdin/stdout） | 要管进程生命周期、崩溃重启、版本对齐 |

### 6.3 推荐：A+（继续走桥，但**收敛成一个入口**，参数与统一工具面 1:1）

理由四条：

1. **判据只有一份**。桥直接调上游 `execute()`，统一模块改一次插件立刻跟随；走 HTTP 就要在路由层再写一层映射，两份判据必然漂移——而 C1–C15 这 15 条冲突正是"两份判据"的产物。
2. **授权不同**。材料路由靠页面会话 cookie（`lib/persistence/owner-claim-http.ts` 是 claim/merge 用的，**不是材料授权**）；插件只有 `OWNER_ID` 常量。走 HTTP 要么加 owner 头（新攻击面），要么改路由授权（风险远大于收益）。
3. **删除会被顺带暴露**。HTTP 侧 DELETE 已存在（`[id]/route.ts:126`、`folders/[id]/route.ts:59`）。插件一旦"学会"调 HTTP，模型离删材料只差一个 action 字符串——这违反 D7，且是**结构性的**（今天是"agent 面根本没有 delete 代码"）。
4. **成本可控**。材料工具调用频率低（一次会话几次到十几次），`spawnSync` 的 1–2s 可接受；26 个其它工具也走同一个桥，材料侧不是瓶颈。真嫌慢，再上选项 C。

**切换到 B 的触发条件（三条齐了再切）**：① 统一模块能给出稳定的 JSON 命令面（工具定义由同一份 schema 生成）；② 材料路由有非 cookie 的 owner 授权（token / mTLS）；③ 删除被拆到独立路由或独立权限。切换时**显式白名单动词**，绝不转发 DELETE。

### 6.4 插件侧具体改法（三条）

1. **合成一个 `openmaic_material`**，`action ∈ {list, read, search, add, prepare, organize, read_topic, write_topic, media}`，与 §4 同名同形；旧三个名字保留一个版本作为 deprecated 转发。
2. **删掉"scope 默认 library"的补丁**（`diag.mts:1429-1431`）：统一后没有 scope，改为在返回里透传 `source`；同时删掉自造 sessionId 的代码（`:1378-1385`）——统一后 list 不应依赖会话 id。
3. **`materialIds` 从"逗号分隔字符串"改成 JSON 数组**（今天是字符串，模型常写错；`:2778-2785` 只拷贝固定字段，改数组要同时改 inner 拷贝白名单）；保留一版"逗号串也认"的兼容。

## 7 风险与不知道

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| R1 | **改工具名会同时改提示词，废掉会话前缀缓存** | `material-prompt.ts:1-16` 明说这块在提示词头部、与材料集合无关（改一字节废整个前缀缓存）；`:24-30` 点名了 `nextBefore`/`before`/`scope`/`top-level` | 一次性改完并同步 schema；不许"先改工具名、后改提示词" |
| R2 | **去 scope 会让未 attach 的库材料涌进会话列表** | 今天 library 分支可达（`material-tools.ts` list 的 library 分支）、会话分支只到 links（`material-resolver.ts:101-123`），且那里有 200 硬上限 | 统一后必须**真分页**；`limit` 默认 50，硬顶 200，超了明确 `truncated` |
| R3 | **主题文件并入要新增 revision 存储** | 今天文件型没有 revision（C6）；`expectedRevision` 是**新行为**，旧调用会失败 | 首版允许"不带 → 覆盖 + `details.forced:true`"，一个版本后转强制 |
| R4 | **`import_pptx` 该不该并入 `add_materials`** | 它改的是**课件页面**（stage 追加页），不是材料库。并进去让"加"有副作用；不并则"加"有两个入口 | **建议一期不并入**，只在提示词里说明它是材料的消费方。等 Stage 模块统一时再谈 |
| R5 | **池资产（`ast_`）与材料的边界** | 今天只有 `use_material_media` 认 `ast_`（`material-media.ts:85`），材料工具一律拒收 | 若将来要"把生成的图登记成材料"，需要新的登记路径，本规格不预设计 |
| R6 | **多教师共享课里 owner 是谁** | owner 是 run 的（`runner.ts:1770` 注释）；D2 说课程库与个人库分开，但**课程级 owner 还没有建模** | 一期沿用 run owner；写进 §4.0 的"owner 永不出现"是为了将来换实现时不动工具面 |
| R7 | **检索粒度：material 级还是 chunk 级** | D5 决定按 2000 字符切块，但今天 `search_material` 返回的是 material 级 + 字符区间（`material-tools.ts:823` 段），**没有 chunkId** | 一期保持字符区间（不引入新概念），块只做内部索引；若日后要给"引用到块"，再加 `chunkId` 字段（向后兼容） |
| R8 | **删除的结构性风险** | 若统一模块让 HTTP 路由与工具共用同一个 service，一次重构就可能把 delete 漏给模型 | service 拆 `MaterialAgentService` / `MaterialAdminService`，只有 admin 能 import `deleteMaterial`（`material-library.ts:471`）与 `deleteMaterialFolder`（`:284`）；测试里断言 agent 面对象上**没有**这两个方法 |
| R9 | **"未配置"的双保险要拆成一处** | 今天 `runner.ts:1568-1570` 条件注册 + 工具内再判（`materials-library.ts:241`） | 只留"不注册"；否则模型会看到一个永远报错的工具（C15） |
| R10 | **15 条冲突里有 4 条是"文案/校验"而非"逻辑"** | C10（4 个长度上限）、C13（三套词汇）、C14（幂等）、C11（top-level 两种表示） | 这四条**不需要改结构**，只需要收敛常量与 copy，可以独立于工具重命名先行落地 |

**不知道**：

- 插件仓另外 26 个工具是否也有材料相关副作用（我只逐字节核了 material 三个工具的存在与一致性，没审另外 26 个）。
