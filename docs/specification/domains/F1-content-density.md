# F1 内容密度与页面形态

## 域的范围

管「一页上放多少字、以什么形态放、放不下时往哪走」：正文字量、元素形态、字号下限、溢出与加页的取舍。
不管一页要讲什么内容（那是课程设计的事），也不管读者用什么动作翻页（F2）、自检页要几道题（F3）。
判定只看渲染后的可算事实：元素边界、文字实际占高、字号取值 —— 不看「好不好看」。

## 规格

### SR-F1.1 每页内容必须在画布可视范围内完整呈现，不得依赖滚动或被裁切

**规则**：一页渲染后，承载内容的每个元素必须整块落在画布可视区域内：元素边界不得越过画布边界；两个元素不得互相遮挡到任一方文字读不全；单块文字的实际排版高度不得超过它自己盒子的可用高度。当上述任一条不成立时，必须整页重排或拆页。不得把「读者会自己往下滚」当成通过条件 —— 阅读页上不存在可滚的正文区。

**为什么是这条线**：画布是固定的 1000×562.5，页内没有滚动条，出界就是直接看不见，且页面上不会有任何提示。实测的一批溢出页里，实时溢出量在十几像素量级（真实溢出 +12px，而估算误报的那批余量只有 +2px）—— 也就是说真溢出长得像「贴边」而不像坏页，肉眼分辨不出，只能按边界判。

**违反长什么样**：一段正文的元素底边压在画布下沿之外，读者看到的最后一行其实是段落的倒数第二行；两个文本框叠在一起，下面那段的字被盖掉一半。

### SR-F1.2 页面内容必须经由 Writing DSL 落成 canvas 元素，不得以纯文本/Markdown 直接投屏

**规则**：幻灯片页的正文必须写成画布上的结构化元素，每个元素带自己的位置与尺寸（文本、形状、表格、代码、公式、图片各按其类型承载对应的内容）。不得把一整份 Markdown 源文或一整段纯文本塞进单个元素充当整页；不得依赖渲染器把 Markdown 语法转成版面。数学必须落在公式元素上，不得把公式源文留在文本元素里。当要讲的内容没有合适的元素类型时，必须改写内容形态或换一种页型，不得降级成一坨文本。

**为什么是这条线**：写入路径不做事后加工 —— 没有标记白名单、没有字号与颜色归一化、没有几何裁剪，结构合法就原样落库、原样上屏。于是「把 Markdown 丢上去」的结果不是被渲染成版面，而是读者在屏幕上看见 `##` 和 `-`。公式留在文本元素里是同一形状的高频真实失败：读者读到的是反斜杠与花括号，不是公式。

**违反长什么样**：整页只有一个文本框，内容以 `##` 开头、下面是一串 `-` 列表；或正文里躺着 `\sum_{i=1}^{n} i` 这串源文。

### SR-F1.3 单页正文目标密度 350–400 汉字；低于目标必须补内容，不得留白

**规则**：一页幻灯片的正文（不含标题、页脚、装饰性文字）目标区间为 350–400 汉字，或以 180–220 英文单词计。低于下限时必须补充实质内容：展开机制、给具体例子、说明它在什么条件下不适用。不得用重复、同义改写、无信息量的过渡句凑数。当材料本身撑不满一页时，必须补的是「这一页要讲清的那件事」，或把这页与相邻页合并，不得靠排版把一页摊成两页。

**为什么是这条线**：默认产出实测只有 61 汉字/页，而同一位老师（天津大学《程序设计》周次讲义）的真实课件实测 352–390 字/页，差约 4 倍。读者的原话是「幻灯片好粗糙，内容单薄，不如我自学」——他要的信息量在一屏里根本不够看。密度不是可调偏好：4 倍的差距决定了这一页是「一屏能读完的知识点」还是「一个标题加一句定义」。

**违反长什么样**：一页只有「变量是存储数据的容器」加一张装饰图；或为了凑够字数，把同一句话换三种说法讲三遍。

### SR-F1.4 内容超出单页容量时必须**加页**，不得压字号、不得删内容

**规则**：当一页的内容在可读字号下放不进画布时，允许的动作只有两种：拆成两页，或补一页。不得缩小字号、不得压行距、不得删掉句子成分、不得删掉例子，以此换取空间。拆分必须落在语义边界上（一个知识点、一个步骤、一段代码），不得把一句话拆到两页。判定「放不进」必须发生在写入之前；写入被拒绝时不得原样重试，必须改成缩到容量内或拆页后再写。

**为什么是这条线**：这块画布在可读字号下的物理容量就那么大，超出的部分只能从字号里挤 —— 先掉到 12px，再掉到 10px，屏幕上就是一整页灰块：内容「都在」，但读不了。实测真实课件的正文是 16px 起。另一面同样重要：350–400 这个数字是实测出来的容量，不是要凑的指标，所以内容多的正确解法永远是加页，删内容就是在用一个更高的代价（讲不清）换一个更低的代价（放得下）。

**违反长什么样**：把一个装不下的段落从 16px 调到 11px，让它「进去了」；或删掉主语和宾语把字数压下来，句子变成「为真走 if」这种读不通的残句。

### SR-F1.5 字号下限必须守住，不得为塞内容把 `fontSize` 压到可读阈值以下

**规则**：页面上承载正文的文字元素，其字号不得低于可读下限 —— 该下限取 14px，依据是真实课件正文从 16px 起。低于下限的页面不得被视为完成，必须重排或拆页。页码、水印等非阅读性文字不在此列，但不得以「把它标成装饰」的方式把正文降到下限以下。判定按整块文字的最大字号取值，标题不得被用来替正文过关。

**为什么是这条线**：14px 这个数不是拍的：真实课件正文 16px 起，而「1000×562.5 画布能装 350–400 字」这个容量结论正是以可读字号为前提算出来的。一旦字号跌破它，「放得下」就变成假命题 —— 字一个不少，但读者得眯着眼读，视线跟不上行。学习者点过的失败模式原话就是「缩成灰块」。

**违反长什么样**：为了把多出来的一段塞进已有文本框，把整块正文从 16px 改成 12px；或字号压到 10px 之后仍然报「本页已完成」。
