# F11 学习状态与回流

## 域的范围

管「学完之后留下了什么」这条路的约束：答题判分落不落库、掌握度按哪种粒度成立、先修关系凭什么成立、练习结果怎么回流、哪些文件是机器产物。

不管题怎么出（F3）、也不管页面怎么读（F2）—— 只管**一次学习行为结束后，什么被记下来了、以什么粒度记、以及凭什么相信这个记录**。

本域含四条**未落地**的规格（SR-F11.4 知识图谱形态、SR-F11.6 笔记层、SR-F11.8 概念身份归并、SR-F11.9 提案态），它们在这里是为了让「打算做什么」与「做到了什么」写在同一个编号体系里。★ 2026-11-10 更正一处：SR-F11.4 的**结构**已落（图谱版本表 + 概念表 expand + 重测链，有 5 条源码判据），但它的**使用**（按 `prereq` 排序 / 版本推进流程 / 导入批次）仍然零，所以它继续留在这一组里 —— 「表建了」不等于「这条规格成立」。其余三条在实现层追踪表与覆盖矩阵里仍标为「无」。

## 规格

### SR-F11.1 答题判分结果必须落库，且必须能从原始作答重算

**规则**：一次自检页交卷之后，逐题的对错必须作为一个可查询的记录持久化，不得只留在「本次作答快照」里由读取方临时推算。记录必须同时容纳两种获得方式：判分结果本身，以及足以重算它的原始输入（选了哪些项 + 当时那一页的题面）。页面被重新生成后，旧记录不得因此变得无法解释。

**为什么是这条线**：现有记录流只存「选了什么」，对错是读取时用题面重算的 —— 这在本机是成立的（174 条记录按最新快照重判，与库内已有判分 48 道题 48 道一致、0 分歧），但它依赖「题面还在」。而题面并不保证还在：`document_scene_revision` 只有 `(stage_id, scene_id, rev)` 三列、252 行，**没有一个字节的页面内容**；实测已有一组 15 条记录锚在一个后来被重生成成别的页面的 `sceneId` 上，那 8 道题的题面与考点永久丢失。判分能算出来，但「错在哪」再也说不出来。

**违反长什么样**：数据库里搜遍所有列都找不到「这道题对不对」，只能靠把页面 JSON 拉出来重跑一遍判分；某天页面被重生成，历史答题记录从此显示「无法解释」。

### SR-F11.2 掌握度必须按页、按题、按知识点三种粒度分开记录，不得跨粒度推算

**规则**：三种粒度的结论各自独立成立、各自标注来源。缺某一级的观测时，该级必须表现为「不知道」，不得用相邻级的数字代替。任何展示给读者或模型的掌握度，都必须能指出它来自哪一级、由多少条观测支撑。

**为什么是这条线**：三级的信息量差得很远，而覆盖率差得更远。全库 234 个页面 100% 带 `outlineId`，但只有 138 页能对上计划条目，其中仅 37 页的条目带 `keyPoints`（Java 一门课占全部 37 页）；另外 6 门课连计划条目都没有。这意味着「页级」几乎处处有，「知识点级」只有一门课有 —— 一旦允许用页级去填知识点级，整库立刻会显示成「处处都已掌握」，而那只是「每页都答过几道题」。

**今天到哪了（2026-11-09）**：题级**映射**已落库（`xq_question_concept` 71 行 / 13 页，来自**题干**命中种子图，强档 35 行 / 弱档 36 行；17 个 quiz 页里 4 页零命中且不是算法能救的），但**判定仍只有页级** —— `xq_cell_state` 是 `(stage_id, scene_id)` 的缓存（★ 知识点级已于 2026-11-10 补上，见下面「知识点级读数来了」；这句保留它当时的读数，不是现状）。所以状态块里那一行「概念『类与对象』」是**页级判定的标签**，不是知识点级结论；把它读成「你掌握了这个知识点」正是本条要防的事。

**题级映射用在了哪里（2026-11-09）**：`xq_question_concept` 目前只被两处读，都是**标注**不是判定 —— 状态块拿它当一格的人话标签（最高档恰好 1 个概念才给），错题排期拿它当四关挂的概念（同一套「唯一才用」规则）。所以「三级分开」这条规格今天成立的部分是：**题级映射存在且被用上**，**知识点级在 2026-11-10 之后有了自己的读数**（`readConceptMastery()`，见下段）；**仍然不成立的是题级** —— 一道题只有「对/错/半题」的行，没有任何地方把它折成三态，也没有人展示过「这道题他到底会不会」。今天三级里两有一无，而缺的那一级最小：一道题的证据通常只有一两条，折成三态几乎总是 `too-few-items`。这不是留了下来没做，是**做出来也不会比上面两级多说什么**；等一道题能被观测三次以上（同题重测、变体、跨轮）再谈。

**知识点级读数来了（2026-11-10）**：`lib/persistence/xq-concept-mastery.ts` 的 `readConceptMastery()` 把同一个概念跨课跨页的全部观测合到一处，用**同一个** `classifyEvidence()` 折叠成三态。三条与页级刻意不同的选择：

1. **算而不存** —— 不建 `xq_concept_state`。加一张缓存表就要回答「证据变了谁去重算」，而那是第二条刷新链（`SR-F11.13` 刚因为「只在 agent 运行开头刷」出过一次错）。今天规模是 56 条证据 / 104 个概念，读全表比维护缓存便宜。
2. **盲猜率按题型分开** —— 页级一格单选多选混着，取哪个都是编；概念级拿得到每道题的 `type`，单选 `GUESS_RATE_CHOICE`（0.25）、多选 `GUESS_RATE_MULTIPLE_MEAN`（0.0638）。页级**不**补这个口径：那会改动已标定的判据（7/8 即可、0.8836 检出率），而标定是按 0.25 做的。两级用不同盲猜率是刻意的。
3. **题目身份是三元组** —— `(stage, scene, question)`，不是题号。题号只在页内唯一（234 页里 35 个 scene id 跨课复用），只按题号去重会把三门课的 `q1` 数成一道。

★ 它**不**回答「今天该学什么」：同 `xq-concept-graph.ts` 的边界，读数是判据、排序是产品决策。

**第一处消费：复习卡（2026-11-10）**：`GET /api/persistence/xq/reviews` 的每张卡顺带一个 `mastery`。三个刻意的细节 ——

- **不传 `stageIds`**：一个概念可能在三门课上各考过一道，只统计「今天恰好有到期关的那几门」会把别的课的证据悄悄排除掉，而排除之后照样给出一个看着很确定的读数（「暂未定（1 题）」），比不给更坏。
- **`null` 与「暂未定」分开**：`null` 是「这个概念一条可判证据都没有」，卡片上不显示那一行；`unknown` 是「有证据但不够判」，显示出来。两件事差得很远，画成同一句就是在编。
- **算失败不影响排期**：`readConceptMastery` 抛错时只 `log.warn`，卡片照常返回 —— 「今天该复习什么」比「他大概会不会」重要。

真库实测（2026-11-10，`.tmp/_cm_real.mjs` + 真路由）：56 条证据里 **17 条**能映射到唯一概念，覆盖 **15 个概念**；三门课那句「Dart 变量 var / final / const」2 题全对、`setState 与状态管理` 2 题 1 对、`字符串` 2 题 2 对 —— 全部低于 `MIN_ITEMS_FOR_VERDICT = 3`，所以真库上今天**每个概念都是 `unknown` / `too-few-items`**。这正是这条规格想说的事：跨过了门槛才配叫读数，没跨过就说没跨过。

**第二处消费：状态块（2026-11-10）**：`refreshLearnerStateFromRuntime()` 把 `readConceptMastery()` 的结果一起折进状态块，排在页级三节**前面**。四条刻意的细节 ——

- **只列已经判得出来的**（`known` / `not-learned`），`unknown` 一条都不列。知识点层存在的意义是跨页合并把证据凑够；没凑够时页级那三节已经把「为什么不够判」写得更细（`再做对 N 题可判` / `证据不一致`），再抄 14 个「暂未定」只多占前缀预算，一个字的信息都不多。
- **一行里不写 stage/scene**：概念是跨页的，写一个页 id 就等于把它钉回某一页，而它恰恰是「两页合起来才够判」的产物。要定位它出现在哪几页是 `GET /api/persistence/xq/concepts?id=` 的活。
- **只写 `n` 不写 `questions`**：`n` 是加权后的证据条数（同日同题重测算半份），`questions` 是去重后的题目个数。两个数都给、都叫「题数」，读的人一定会混；判据实际用的是 `n`，题目个数留在接口里给界面用。
- **节名主语换了但阈值照写**：`## 知识点：已达判据（跨页合并，置信下界 ≥ 0.55，且 3 天后复测仍答对）`。页级那三节的主语是**页**，这两节的主语是**知识点**；同一个数字在两处都写一遍是刻意的 —— 读者不该为了核对一个阈值去翻另一节。

★ 真机读数（2026-11-10，`.tmp/_refresh_concepts2.mjs`）：`cells=6 / concepts=15 / reviews=0`，15 个概念**全部** `unknown`/`too-few-items` ⇒ 状态块里这两节一行都没有，文件字节数与加这一层之前**完全相同**（1573 B）。链路通、内容不变，这是设计要的结果：没有跨过门槛就不该出现在给人看的地方。

**违反长什么样**：某页 8 道题全对，于是学习状态里写成「已掌握 OOP」；或者知识点级空缺时按 0 分显示，让人以为「考了但没会」而不是「没测过」；或者把「1 题答对了」当成「这个概念会了」。

### SR-F11.3 先修关系必须带来源与置信度，无证据不得参与排序

**规则**：任何「A 应先于 B」的判断都必须带三样：来源（人写的、从语料统计的、从外部图谱映射的）、置信度、以及它覆盖到哪一级。置信度不足或来源不明的边不得用于生成学习顺序，也不得用于判定「前置没打牢」。相似不等于先修 —— 仅仅因为两个概念在语料里相邻或字面相近，不构成先修证据。

**为什么是这条线**：这是本库实测踩到的坑。拿一张外部算法竞赛图谱（130 节点 / 158 条先修边）去匹配本库 234 页，只命中 10 页，其中 8 页是同形异义 —— 站点里「构造」指构造题，Java 课里指构造方法。同一张图的 `tier` 字段也不是拓扑层级：16 个 `tier=0` 的节点有先修入边（分支结构←顺序结构、数组←循环结构……）。若按「层级低就先学」排序，从第一页就是错的。

**违反长什么样**：因为两门课都讲「构造」，于是判定「学完 Java 的构造方法就能做构造题」；或者把一张外部图的层级字段当先修层直接用。

### SR-F11.4 课程必须以可演进的知识图谱为基准，图谱的增删改必须可追溯（**未落地**）

**规则**：课程与概念的关系由一个独立的、可版本化的图谱承载，而不是硬编码进页面或提示词。图谱的三类变更必须各有明确语义：新增类型/新增节点是 additive、不触发对既有数据的迁移；修改既有类型的属性必须整体迁移，且**不允许半迁移状态跨越一次重启存在**；删除概念必须留下可解释的墓碑，不得让指向它的学习记录变成无法解释的孤儿。改名必须在原地改显示名、保住标识，否则所有历史记录都要改读路径才能读出新名。

**为什么是这条线**：课程是一门门加进来的，概念会拆、会并、会改名。本库当前**没有任何图谱结构**（全库没有概念表、没有先修表），最接近概念载体的 `keyPoints` 只覆盖 37 页。一旦按「先建起来再说」的写法把概念写进页面，改名就等于重写全部课程页。

**为什么仍标「未落地」**：形态定了、表建了、数据也有了（见上），但**使用**那一半仍有两条没做 —— 没有按图谱排序、没有导入批次落地（版本推进流程 2026-11-10 已有，见下）。这一节因此继续只写约束，不写落点。**版本推进流程来了（2026-11-10）**：`lib/persistence/xq-graph-version.ts` 有三件事 —— `readGraphVersions()` 读版本链与每版概念数、`advanceGraphVersion()` 冻结旧版并开出新版、`assignConceptsToVersion()` 把 `created_in IS NULL` 的概念钉到某一版。入口是脚本 `scripts/advance-graph-version.ts`（**故意不是 HTTP 路由**：推进是一次导入的边界，两次推进之间必须有真实导入，而它的失败模式是「另一个窗口先推进了」——那要人看一眼再决定）。

三条写死的约束：

- **推进必须带 `from`（比较并交换）**。只写 `max(version)+1` 会让两条并发调用都成功，中间那一版一秒钟都没开放过，`created_in` 永远不会有概念，版本链上却多一个空档。`ADVANCE_SQL` 一条语句三个 CTE，`frozen_n != 1` 或新号不等于 `from+1` 就整条不生效。
- **`created_in` 只写一次**。`assignConceptsToVersion()` 只碰 `created_in IS NULL` 的行 —— 重写它等于篡改历史，「这个概念是哪一版进来的」就不再是可核对的事实。
- **冻结的版本不再长**。往已冻结的版本里塞概念直接抛 `RangeError`。

真机读数（2026-11-10，跑完即还原）：`--dry-run` 打印 `1 版 / v1 open / concepts=104`；真跑 `--label v2` ⇒ `v1 frozen (concepts=104) / v2 open (concepts=0)`；重跑同一条命令回 `already-frozen`（退出码 2，不是静默成功）；`--from 2`（不存在的版本）回 `not-found`（退出码 2）。判据 `tests/persistence/xq-graph-version.test.ts` 17 条。

**仍不成立**：版本推进有了入口，但**没有任何导入批次会真的调用它** —— `xq_intake_task` / `xq_intake_proposal` / `xq_alignment_unit` 三张表仍是 0 行，`created_in` 也没有第三个值出现过（104 个概念全在第 1 版）。所以「版本化」今天是**可用的能力**，不是**在用的机制**。

**在有人真的按 `prereq` 边排出顺序之前，任何「按图谱排序」的行为都不许上线。**（原句写的是「形态还没定」，2026-11-10 更正：形态已经定了，缺的是用它的那一步。）

**违反长什么样**：把概念名直接当主键写进页面标题；改一个概念名需要重跑 200 多页；删掉一个概念后，学习状态里出现指向不存在概念的记录且无人能解释。

**今天到哪了（2026-11-10）**：**结构齐了，使用没有**。
- 概念图五张表都在且都有数据：`xq_concept` **104 行**（不透明 id `c_`+12hex）、`xq_concept_alias` **357 行**、`xq_concept_external_ref` **63 行**、`xq_concept_edge` **105 行**（`prereq` 94 / `contains` 11）、`xq_concept_occurrence` **644 行**。
- **版本化 2026-11-10 落地**（迁移 `3 graph-version` + `4 concept-expand`）：`xq_graph_version` 存在且已有 `1 baseline` 未冻结；`xq_concept` 补了 `anchors / created_in / retired_in / revived_at / updated_at` 五列，既有 104 行回填到第 1 版；四条约束（id 形状、名字非空、两条版本外键、退役顺序）在库上生效。同一时刻只能有一个开放版本由偏索引 `xq_graph_version_one_open ON ((true)) WHERE frozen_at IS NULL` 管住 —— 冒第二行会 `duplicate key value violates unique constraint`。
- 但**版本的推进流程一条都没写**：没有人调「冻结旧版 + 开新版 + 给新概念写 `created_in`」，也没有导入批次与它对接（`xq_intake_task` / `xq_intake_proposal` / `xq_alignment_unit` 三张表**都是 0 行**）。
- **读侧有了（2026-11-10）**：`lib/persistence/xq-concept-graph.ts` + `GET /api/persistence/xq/concepts` 是这 94 条边**第一次**被读。它回答的是图上可算的问题 —— 直接先修、传递闭包、最长先修深度、环、退役先修、以及「按给定已掌握集合现在能不能学」——**不产出任何顺序**。
- 更关键的一条没变：**没有任何「按图谱排序」的行为上线**。读侧存在不等于排序被允许，本节末句仍然生效。
- 读侧实测（2026-11-10，真库 104 概念）：`GET /xq/concepts` 回 104 / 105 边，`prereq` 按强度 5 strict / 88 recommended / 1 helpful；对全部 104 个概念逐个调 `?id=` 与独立的 Kahn 最长路径比对，**深度 0 处不一致**，`notReady` 74（= 104 − 30 个无先修），环 0。
- **出现记录也一起读了**：`xq_concept_occurrence` 644 行（keypoint 17 / title 127 / body 500）此前同样零生产读方，现在随 `?id=` 一并回「这个概念出现在哪些页、页标题、权重、命中层级」。75 个概念有出现记录，**29 个一条也没有** —— 如实回空数组。真库直读：`类与对象` 58 条、按 `weight DESC` 排在 `keypoint(1.0)` → `title(0.6)` → `body(0.4)`，标题 58/58 全部解析出来。


### SR-F11.5 练习结果必须回流进学习状态，读取失败必须表现为「没有记录」

**规则**：练习跑完后写出的结果文件必须被学习状态的组装过程真的读到，并与答题记录并列呈现、各自标注来源。读取失败（文件不存在、格式坏、目录不在）必须表现为「这一类记录没有」，不得表现为「沿用上一次读到的那份」，也不得让整次状态刷新失败。

**为什么是这条线**：练习是「一次布置看不出能力」时唯一的重复信号，写了不读等于白做。这条链在本机已经通了：19 个练习文件夹各带一份判据清单（共 69 条判据）与一个判分脚本，实跑一页能生成 725 字节的结果文件（3 条判据过 2 条）；读取端按固定三层目录扫描、坏文件跳过、按时间倒序，并已接进状态文件的「## 练习」段。但**目前全库只有 1 份结果文件**（19 个练习里）—— 链路通，不等于数据在。

**违反长什么样**：练习跑完了，学习状态里只有答题记录、没有练习那一节；或者结果文件被删掉之后，状态里还留着上一次的「2/3 通过」。

### SR-F11.6 笔记层可以作为学习痕迹的载体，但不得成为状态的唯一真相（**未落地**）

**规则**：笔记可以被读取、被写入、被当作证据引用，但掌握度这一类需要重算的结论不得只存在于笔记的元数据里。笔记里的状态痕迹必须能重建；把状态拆散写进每篇笔记的元数据，等于让格式化、排序、插件各改一次就丢一次。写入必须默认不落盘（先算差集），并带内容指纹前置校验与独占锁 —— 只有校验没有锁是不够的。

**为什么是这条线**：本机 vault 有 697 篇笔记、260 万字符，但元数据顶层键**只有 `tags` 一个**（557 篇有），没有任何状态字段 —— 想挂状态就得新造一套约定，而约定一造出来就会被格式化工具重写。已有的写入工具带内容指纹校验，但实测**挡不住并发**：双进程同指纹对写 40 轮，15%（6/40）静默丢更新，两个写者都回报「通过」。所以这条的判据不是「有校验」，是「有锁」。

**为什么标「未落地」**：笔记层还没接进来（OpenMAIC 与 Obsidian 至今零集成）；2026-11-09 只落了只读侧的第一层（`lib/notes/local-kb.ts`，严格口径检索），写侧一行代码都没有。**独占锁未实现，双写者场景实测 15% 静默丢更新（40 轮 6 次），因此在锁落地前，笔记只当人读的材料。**

**读侧现在到哪了（2026-11-09）**：`lib/notes/local-kb.ts` 已经能查，但**没有任何生产调用方** —— 全仓 `findNotesForConcept` 的引用只出现在它自己的测试里（`tests/notes/local-kb.test.ts`），`lib/server/agent-runtime/` 与 `app/` 都没有 import 它。这是**刻意**的：`docs/research/材料统一/07-合成设计与实施拆分.md` §7 早已裁决「pika 三技能不接进工具面，个人知识库是另一个房东」，所以它只作为服务端只读库模块存在，不注册成 agent 工具。⇒ 「笔记层接进来了」这句话现在**不成立**；成立的只有「有一个能查的函数，还没有人调它」。另外它查得到的极少：真库 697 篇里，104 个种子概念只有 **7 个**的标题或小节路径里真的有那个名字（`引用 / Git / 反函数 / 连续 / 单调有界 / 实分析 / 线性代数`），其余 97 个概念**一篇笔记都没有**。所以判据不该写成「任意概念都能查到 ≤ 5 篇」，而该写成「**查不到是常态，查到才列**」。

**违反长什么样**：掌握度写进每篇笔记的元数据，跑一次格式化之后状态全丢；或者两个进程同时写同一篇笔记，后写的静默覆盖先写的而双方都以为成功。

### SR-F11.7 机器生成的产物必须自证身份，人写与机写必须分文件

**规则**：由代码生成的、供人读或供模型读的状态文件，必须在文件里写明「由谁生成、什么时候生成、不要手改」；人可以直接编辑的那份必须与它分开，两者矛盾时以人写的那份为准并显式说明矛盾。同一份事实不得同时存在于两个人的可写位置。

**为什么是这条线**：两份学习者文件当初正好是反面教材。一份 946 字节全部由代码生成（2026-11-09 读数；今天是 1798 字节四节 —— 多了归属注释、矛盾节与练习节，但「两节」这个形状当时是真的），人改一个字下次运行就被覆盖，**而在 2026-11-10 之前没有任何地方写明「不要手改」**；另一份 1851 字节是人写的，两份互相矛盾 —— 人写的那份说「Dart/Flutter 未知」，机写的那份记着这两门课错了 4 道。模型在同一轮里读到两句互斥的话，两句都被标注为「当作事实」。

**违反长什么样**：人手工在机器产物里补了一条笔记，下一轮消失且无任何提示；或者人写的「我不会这台机器」与机器写的「这两门课你错了 4 道」同时出现在上下文里，模型随机相信一边。

**「不要手改」这一句来了（2026-11-10）**：渲染器现在在块首那行声明**之后**写一行 HTML 注释 ——

> `<!-- 本文件由代码生成（学习状态刷新器）。手改会在下一次刷新时被整段覆盖 —— 要改判定，改库与判据，不要改这里。 -->`

选 HTML 注释不是随手：块内不许出现元指令（渲染器约束 2），而注入链路 `prompt-context-file.ts` 的 `HTML_COMMENT` 会把注释整段剥掉 —— 所以这句话**人打开文件看得到、模型读到的那段里一个字符都没有**，正好落在「声明归属」这一层而不违反约束 2。真机验过两侧：磁盘文件 1405 → 1573 字节且第三行就是这句注释；`readPromptContextFile` 读出来的仍是 1405 字节、首行仍是那句声明、`<!--` 一个都不剩。判据四组：渲染器里这句在（`tests/quiz/learner-state-render.test.ts` 的「约束 7」四例）与注入后这句不在（`tests/agent-runtime/learner-state-provenance.test.ts` 四例，含「只有一处投影」）。

**矛盾检出这一句的机器那一半来了（2026-11-10）**

原来的判据草案是「画像里任何一行 `X = UNKNOWN`，不得同时存在同领域 `tri != 'unknown'` 的格」。按它做会**永远不红**，不是因为没矛盾，是因为匹配不上：真库实测 `Dart`、`Java`、`程序设计基础` 在 `xq_concept.canonical_name` 与 `xq_concept_alias.alias` 上**精确命中 0 条**（`Dart` 只有 `Dart 变量 var / final / const` 这种长名，`Java` 一条都没有）。

所以换了链路：**域 → 页标题 → 格**。课程名在页标题里是原样出现的（真库 234 页里 `stage--ShZtYAYOj` 有 6 页标题带 Dart、5 页带 Flutter，`stage-GYvpbYB_aN` 有 3 页带 Java），而格是挂在页上的。`lib/server/agent-runtime/profile-contradictions.ts` 只做这一件事：把画像里标 `UNKNOWN` 的领域切成词，去匹配那些**非 `unknown` 的格**的页标题。

三条已知的误报，写在这里而不是写进代码注释里，因为它是这条判据的适用边界：

1. 标题里出现「别用 Java 的思路写 Dart」这种否定句时，会被算作 Java 的证据。
2. 整门课的页标题都带课程名时，域内任何一页判出来都会触发 —— 那不是错，只是它提示的是「这门课里有页判出来了」，不是「这一页属于该领域」。
3. 只看标题不看题干：题干里出现的课程名不算证据。

输出是「值得人看一眼」的清单，不是判决书。块里那一节的措辞固定为「画像说 X，状态说 Y」（不带「错误」「应改为」「画像过期」），因为规格已经把优先级写死（矛盾时以人写为准），而让状态块替模型裁决等于把「人写的那份可以被机器悄悄推翻」制度化。

真机读数（2026-11-10）：画像 801 字节、`xq_cell_state` 6 格 ⇒ **1 条**矛盾 —— `Dart / Flutter` 标着 UNKNOWN，而「自检：Dart 进阶八道题」n=8 k=8 已达判据（下界 0.782）。同一轮里 `Java` 零命中（它那 3 页都在另一门课、且都不是 `not-learned`/`known`）。块从 840 字节变 957 字节。

**仍不成立的两条**：① 文件里**没有**写明「什么时候生成」—— 写具体时刻会让每次刷新都变一个字节，而这一行存在的意义是「说明它会变」；精确时刻在库里（`xq_session.recorded_at`），不在给人看的散文里。② 人写/机写的**矛盾仍不能被机器发现**：判据要写成「画像里任何一行形如 `X = UNKNOWN`，不得同时存在同领域 `tri != 'unknown'` 的格」，但实测画像里的 `Dart` 与 `Java` 在概念表里**一个都查不到**（`Dart` 别名 0 命中、规范名 0 命中；`Java` 同样 0/0），「`Dart / Flutter`」整个字符串也对不上 `Flutter` 这个规范名 —— 直接按字符串匹配写，这条判据在真库上会**永远不红**（不是因为没矛盾，是因为匹配不上）。要做这条得先有一张「画像域 → 概念 id」的人工映射表，那是新数据，不是新判据。

### SR-F11.8 外来课程与既有图谱重合的概念必须归并到同一个身份，不得因来源不同而分裂

**规则**：同一门学科的概念在不同课程里被重复讲到时，整个系统里只能有一个概念身份。名字（中英文、别名、外来图谱的叫法）可以有多个，但都指向同一标识；来源（哪门课、哪份外来图谱）记在边上，不记在身份上。外部图谱的标识只能作为**外部引用**保存，不得直接充当本系统的概念标识 —— 需要映射表，且映射必须是多对一可寻的（同一个我们的概念可以挂多个外部标识，同一外部标识只能指向一个我们的概念）。

**为什么是这条线**：如果每来一门课就新建一套概念，「函数」在三门课里就是三个节点，学过的证据永远聚不起来，掌握度会永远停在「这门课里会一点」。而「同一个名字在不同课里指不同东西」在同一台机器上已经有 35 个实例（`sceneId` 跨课程复用，其中 34 个连页类型都不同）—— 所以身份既不能靠名字，也不能靠外部 id。业界现成的反例是可复算的：用 `${图 id}:${节点 id}` 前缀拼接做主键，一次按后缀 `split_part` 的 join 会让 3 行静默变 6 行。

**违反长什么样**：同一门「线性代数」导入两次之后，库里出现两套概念，按概念查历史答题记录一半查不到；或者接入第二个外部图谱时，把它的节点 id 直接写进我们表的主键，之后想换图谱就得全量重写历史记录。

### SR-F11.9 外来课程里图谱未覆盖的概念只能以提案身份存在，不得静默收编、不得参与学习排序

**规则**：匹配结果必须分成三段且各自有明确的后续动作：**命中**（归并到既有概念，只加出现记录）、**存疑**（进提案表，等人裁一次，先不改图谱）、**未命中**（也进提案表，但标注为新概念候选）。三段**都不得**自动改变学习顺序。提案的晋升必须是显式动作，且拒绝之后要留痕，使同一份材料再次导入时不重复提案。同形异义的判定不得依赖字面相似度单独成立。

**为什么是这条线**：新内容里既真的有新概念，也有同形异义。拿一张外部算法竞赛图谱（130 节点 / 158 条边）去匹配本库 234 页，命中的 10 页里 **8 页是同形异义** —— 那张图里「构造」指构造题，Java 课里指构造方法。若把「字面命中」当「概念命中」，学习路径会从第一页就排错；那张图的 `tier` 字段还根本不是拓扑层级（16 个 `tier=0` 的节点有先修入边），照它排序同样是错的。

**违反长什么样**：导入一门新课后图谱里凭空多出几十个节点，其中一半是「构造」「排序」这种一词多义；或者提案还没人批，学习路径已经把「未确认的新概念」排在了「已确认的基础」前面。

### SR-F11.10 学习行为必须留下只追加的事件流，会话是事件的包络

**规则**：一次学习行为（翻到某页、交了某题、看了提示）必须作为一条只追加的事件记下来。事件带两个时间（当事人看到的时刻、服务端记下的时刻）与一个幂等键；撤销靠再写一条 `voided` 事件并指向被撤销的那条，不得 UPDATE 或 DELETE 历史行。同一次学习过程由一条会话记录当包络，**会话 id 就是它第一条事件的 id** —— 不发明第二个 ID 生成器。会话里的派生量（活跃时长、看了几页、答了几题）写在会话行上，不得靠每次读取重扫事件表算。

**为什么是这条线**：事件流是状态与画像的**共同上游**，三者只有一个方向：事件 → 状态 → 状态块。没有事件，「今天学了多久」「这一课重看过几次」「复习是打开过还是真的做了」这类问题只能靠猜。而实测这条链此前是空的：`xq_event` 的 16 个 kind 的 CHECK 早就写进迁移了，全仓**零调用点**，页面上翻一页什么也不留。两个时间必须分列，因为客户端时钟可能错、也可能被回填，而服务端记账时刻不许被客户端覆盖。

**违反长什么样**：翻过十页，库里一条记录都没有，只能从运行期记录反推「大概在第 33 页待了一会儿」；或者为了补一条错记直接 UPDATE 历史行 —— 「他当时确实翻到了那页」这件事从此不可考；又或者会话 id 另起一套生成器，于是「这次会话的第一条事件」与「这条会话」永远对不上号。

**今天到哪了（2026-11-09）**：落地的是**这条链的入口**，不是全部分析能力。已成立：16 个 kind 的写入路径、会话包络与当日序号、幂等（同一事件重发两次行数不变）、04:00 跨天、播放态翻页自动记事件（真机端到端跑过：手点三页 → 3 条 `page_viewed`）、**提示分型**（`hint_subtype` 在 2026-11-10 之前根本没有写入路径 —— 字段与列清单里都没有它，于是十六个 kind 里唯一带方向的那个从来没被写过；现在 `hint_requested` 必须带 `instrumental` / `executive`，其余 kind 带它就是写错行）。**读方来了（2026-11-10）**：`lib/persistence/xq-session-digest.ts` 的 `digestSessions()` 是这条事件流的第一个消费端，把 `xq_event` 折成「这次学了多久、今天学了什么」（活跃时长 / 墙钟 / 页数 / 两种提示分开数 / 答过与交卷分开数），路由 `GET /api/persistence/xq/sessions`（`day` 是**学习日**不是日历日，写成 `yyyy-mm-dd` 之外拒 400 而不是忽略 —— 忽略会把「这一天」悄悄放大成「全部」）。判据 10 + 9 条。它**不回写 `xq_session`**：`active_ms` 现算，因为事件还在长。不成立：`self_report` 仍零采集；三档空闲阈值只实现了两档（30 / 60 分钟），**5 分钟那一档故意没做** —— `page_viewed` 不区分「在读这一页」与「正在翻过去」，要分就得知道停留时长，而那正是 `dwell_ms`，今天没有任何写入方给它赋值；凭「翻页」两个字判成 5 分钟会把真读了 50 分钟的人砍成 5 分钟。`dwell_ms` 仍只是列在那儿。

**「学了多久」有界面了（2026-11-10 二续）**：`/sessions` 页（`app/sessions/page.tsx` + `components/learning/session-list.tsx` + `lib/learning/xq-session-client.ts`）把这个端点画出来 —— 一条会话一行（起始时间、分钟数、进行中标记、事件/页数/交卷/问方向的明细），顶上是一天的合计。★ 三条刻意的边界：**读失败不许说成「今天没学」**（一份空的会话列表看起来像「他什么都没做」，而真正原因可能只是服务端没起来 —— 那会让人去怀疑自己的自律）；**合计只累加已结束的会话**（进行中那一个的活跃毫秒只会越算越小，最后一段间隔还没被下一条事件截断，把它加进去会让「今天一共学了多久」这个数**倒退**）；**这一页没有「今天该做什么」**——那是 `/review` 的事，一个读计划（`xq_review_schedule`）一个读事实（`xq_event`），并到一页会让人以为「学了 40 分钟」等于「今天做完了」。这些数字**仍然不进状态块**（N3 §4.4：阈值全是切分参数不是剂量参数，而它们每分钟都在变，进状态块会持续破坏前缀缓存）。判据 `tests/learning/xq-session-client.test.ts` 9 条 + `tests/i18n/sessions-locales.test.ts` 49 条；真机验过端点回 1 个会话、10 分钟、3 页，页面 SSR 出三个状态文案。**会话现在有三种结束方式（2026-11-10 三续）**：播放态 `teardown()`（点返回、切编辑态）、`pagehide`（关标签页、导航离开 —— 这是最常见的离开方式，而它**不会有任何 React 卸载回调**）、以及服务端的会话超时（未实现）。第三个此前是唯一缺的一个，后果很具体：合计只累加**已结束**的会话，所以关标签页那种走法会让「今天学了多久」永远显示 0 分钟。修法两处：`post()` 带 `keepalive: true`（卸载中的页面发普通 fetch 会被浏览器掐掉）、新增 `useXqSessionLifecycle()` 挂 `pagehide`。★ 为什么**不**挂 `visibilitychange`：切标签页只是「手离开了」，不是「不学了」，拿它当结束会把一次学习切成很多段。★ 为什么不是 effect cleanup：StrictMode 双挂载与热更新会让 cleanup 反复跑，把「今天学了 5 次」写成 15 次。

### SR-F11.12 自评必须作为事实记录，且永不得参与判定

**规则**：答题时可以让人给自己的把握打分（四档：25 / 50 / 75 / 95），这一条自评**只进事实表**（`xq_probe_item.confidence_pre`），**不进任何判定式** —— 不得参与掌握度、不得参与掌握/未掌握的三态、不得参与复习排期。它可以被算成「准不准」（预期正确率与实际正确率的差），但那个结论只能给人看，不能反过来改判。

**为什么是这条线**：这是一条**有实验依据的否定式**。Karpicke & Roediger（2008）四组被试在学完之后预测自己一周后的成绩，预测值都落在 **50%** 上下（20.8 / 20.4 / 22.0 / 20.3），而实际成绩是 **80% 对 33%**，组间比较 **F<1** —— 自评与真实掌握**零相关**。零相关的量拿去加权，等于往判定里加噪声，而且加完之后输出的形状完全正常，看不出错。

**四档为什么是 25 / 50 / 75 / 95 而不是 0 / 50 / 100**：两端各留 5% 的谦逊余量。说「基本靠猜」不等于一点不会，说「很有把握」也不等于一定对；用 0 与 100 会让校准曲线永远带着一个系统偏置。

**什么时候问**：写完答案、判分还没开始的那一瞬。做题后立刻回顾（postdiction）与真实成绩的相关约 **0.53**，做题前预测（prediction）约 **0.33** —— 问得越早越不准。复习态**不问**：那时他已知对错，问「当时有多大把握」得到的是回忆，不是预测。

**违反长什么样**：把自评当权重乘进掌握度，于是「很有把握但答错」的那一格反而比「没把握但答对」更接近已掌握；或者自评一填就把某格推成「已掌握」—— 那正是把「他觉得自己会」当成了「他会」。

**今天到哪了（2026-11-10）**：已成立 —— 四档自评的纯判据、payload 承载、视图状态恢复、探针写入、题卡界面（`data-testid="quiz-confidence"`）、校准条（题数不到 8 时只说「还差几道」，不出「你很准」）；十二个 locale 齐；`lib/quiz/xq-mastery.ts` 的 `EvidenceItem` 至今没有、也不许有自评字段（有源码判据守着）。不成立 —— 自评只在**播放态做题页**能填（`/review` 的复习卡还不问）；`confidence_post`（答完之后的回顾）仍零采集；「准不准」只在本页显示一次，没有进状态块，也没有跨会话的趋势。

### SR-F11.13 机器写的状态块必须在「库变了」的那一刻跟上，而不是等下一次运行 agent

**规则**：学习状态文件（机写，路径由 `learnerStatePath()` 决定）是**库的投影**（三样来源：`xq_cell_state` / `xq_review_schedule` / 练习文件夹）。任何让这三样发生变化的生产写路径，都必须在写成功之后触发一次刷新；刷新**失败一律降级、绝不回滚已经成功的写**，也绝不让调用方以为写失败。

**为什么是这条线**：文件是接口（热路径只读文件，见 `lib/server/agent-runtime/learner-state.ts` 文件头），所以「库变了但文件没变」不是缓存慢，而是**一次静默失配** —— 人和模型读到的都是旧事实，而两边都不报错。实测证明它不是理论风险：磁盘那份 **946 字节**、mtime `2026-11-09T05:27:38Z`，而同一时刻用同一个库渲染出来是 **1405 字节**，差的是一整节「练习（真的跑过代码的那些）」。原因不是渲染器坏了，是刷新点只有 `runner.ts` 每轮开头一处 —— 答完题就关掉标签页的人，永远不会再把那份文件刷新到最新。

**违反长什么样**：库里已经记着这次答错、排了四关，状态块却还写着「暂未定」；或者练习文件夹里多了一份 `result.json`，状态块里没有那一节。两种都不会报错，只会让「状态」这个词慢慢失去意义。

**刷新必须是 fire-and-forget**：写路径已经成功了（答题内容在 `runtime_records` 里、复习结果在 `xq_event` 里），刷新只是让一个派生物跟上。若把刷新做成 `await` 并让它的失败冒到调用方，用户会看到「提交失败」而实际答案已经存好 —— 那比状态块旧一天更糟。同理，刷新**不许**因为上一次失败而进重试队列：它是幂等的、下一次写会再触发。

**今天到哪了（2026-11-10）**：已成立 —— `refreshLearnerStateWithConnection(queryable)` 用调用方已有的池子刷，接在两处：`withXqProbeRecording` 的 `onRecorded`（只在真的插了新事实时叫，重复投递不叫）与复习写入成功之后；两处都是 `void`，钩子自己抛错也不会让 append 失败。判据 `tests/agent-runtime/learner-state-refresh.test.ts` 5 条 + `tests/persistence/xq-probe-recorder.test.ts` 里 `onRecorded` 那组 4 条。真机验过：磁盘 946 → 1405 字节，三节齐。不成立 —— 只有这两条写路径接了；练习文件夹里的 `result.json` 是**磁盘**来源，没有任何东西能感知它变了（要等下一次 agent 运行）；也没有任何节流，短时间连答十题会刷十次（每次都是读库 + 比内容 + 偶尔写一次，代价不高，但没有上限）。

### SR-F11.11 计划必须与事实对得上，排出去的关必须收得回来

**规则**：任何「以后要做的事」（排期、待办、到期提醒）都必须有一条明确的收口路径，且收口时**先写事实、再改计划**。计划是从事实派生出来的缓存，不得代替事实被修改 —— 把一次复习结果只写进排期表而不写事件，等于「他这次做错了」这件事从此不可考，而所有基于失败次数的降级规则都算不出来。

**为什么是这条线**：这条链此前正好是半开的。`xq_review_schedule` 在 2026-11-09 的回填写进了 20 关（5 道题 × 四关 1/3/7/15 天），而收口它的方法 `recordReviewOutcome()` **没有任何生产调用方** —— 全仓引用只在它自己的测试里。于是第二天起，那 20 关会永远显示成「今天到期的复习」，谁也消不掉。这不是「二期还没做」：一期已经能排期、能把到期关渲染进状态块，唯独没有人能说「这一关我做完了」。

另外，`review_passed` / `review_failed` 两个 kind 从 S5 起就在 DDL 与 `XQ_EVENT_KINDS` 里，却**从未被生产代码写过一次** —— 而 M 文档 §3.2 分歧四裁决「四关重置降级规则」（做错第几次起不再回到第 1 天）**必须先有失败计数**。计数只能来自这两条事件。计划与事实之间的这道缝，正是降级规则一直无法动工的原因。

**违反长什么样**：排期表里的关到期后永远挂在「今天到期的复习」里，越积越多，学习者最后学会无视那一段；或者为了清掉它直接 UPDATE / DELETE 排期行 —— 「他做过这一关、做错了」这件事从此不可考；或者先改排期后写事件，事件失败时排期已经关掉，事实永久丢失。
