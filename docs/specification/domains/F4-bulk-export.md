# F4 批量导出

## 域的范围

管「一次带走多门课」这件事的约束：一次导出覆盖几门课、归档里装什么、每门课的结果怎么回报。
不管单门课导出的内部格式细节（那是契约层），也不管导出的 PPTX 版式是否好看（F1）。
判定只看三件事：读者需要点几次、归档里能不能真的用、失败的那门课有没有被说清楚。

## 规格

### SR-F4.1 多门课必须能一次导出为单个归档，不得要求逐课点击

**规则**：当读者选中多门课时，必须存在一个动作，一次产出单个归档文件，归档内每门课一个顶层文件夹。不得要求读者逐门课打开、逐门课触发下载。一次导出只允许产出一次下载动作。归档内的文件夹名必须唯一且跨平台可读：同名课程必须自动区分，路径分隔符、保留字符、控制字符与结尾的点或空格必须被处理掉。当读者一门课都没选、或一种工件都没选时，必须在开始前拒绝并说明原因，不得产出一个空归档。

**为什么是这条线**：原来的唯一路径是「打开那门课、进页头菜单、逐个下载」，课一多就是一门门打开；而浏览器本身会拦截一个页面连续触发的多次下载 —— 也就是说这条路不只是慢，它在第十门课左右会直接坏掉。一个归档是唯一同时解决「次数」和「浏览器拦截」的形状。文件夹唯一性不是洁癖：库里同名课程不少（「未命名」、重复导入的行），ZIP 里同名条目会静默覆盖，读者会发现少了一门课而且没有任何报错。

**违反长什么样**：选十门课，导出按钮只导当前打开的那一门；或导出的归档里两门「未命名」课程挤在同一个文件夹，一门的内容被另一门盖掉。

### SR-F4.2 导出必须包含课件可用所需的全部资源，不得只是页面骨架

**规则**：导出必须包含让课件脱离原环境仍可用的全部资源：页面骨架之外，样式、脚本、字体、图片、公式渲染所需的资源、以及交互页与自检页运行所需的数据都必须进归档。外链资源必须被就地内联，或在归档内提供本地副本。当某个外链资源无法取到、无法内联时，必须记录该资源的地址并按课程汇总进导出结果，不得静默跳过。只有骨架没有资源的导出不得被视为成功导出。

**为什么是这条线**：导出的用途是「带走」—— 换一台机器、断网、发给别人，打开还得是同一份课件。只给页面骨架的结果是：结构都在，样式全丢，图片全裂，公式变成源码。这类导出在生成端看起来完全成功（文件写了、字节数不小），只有读者打开时才发现不可用 —— 反馈链路整整晚了一步。资源内联本身会失败（外链取不到是常态），所以「失败要记录」和「内联要做」是同一条规定的两半。

**违反长什么样**：导出的交互页打开后样式全无、图片全是裂图，因为 CSS 与图片还指着远端的地址；或归档里少了几张图，导出结果显示「成功」。

### SR-F4.3 导出必须报告每门课的成功/失败，不得整体静默

**规则**：导出结果必须逐门课给出结论，每门课至少带：课程标识、在归档里的文件夹名、写出的文件清单、没有产出某类工件的原因（例如这门课没有该类页面）、以及失败时的错误说明。一门课失败不得中断其余课程，也不得让其余课程的结果丢失；取消导出则必须整体作废、不保存半成品归档。失败与「这类工件本来就没有」必须是两种不同的结论，不得都写成「空」。

**为什么是这条线**：批量导出最糟的失败不是全挂，而是「挂了六门、看起来全成了」。读者拿到归档、打开、发现少了两门，已经无从知道是哪两门、为什么。反过来，「这类工件本来就没有」被写成失败也会误导：一门纯幻灯片的课没有交互页是正常的，把它算成错误会让读者去找一个不存在的 bug。逐门课的结果是唯一能让人事后定位的形状。

**违反长什么样**：导出中途某门课抛错，整个导出失败、前面已经导好的课全没了；或导出「成功」，结果里只有一句「完成」，读者要自己打开归档数文件夹才知道少了几门。
