# F9 写入闸与版面差集

## 域的范围

管「把一份改动落到页面上」这条路的**全部约束**：写之前拦住不该写的，写的时候保证原子，写之后证明改对了。
不管「内容该写什么」（F1）、也不管「多个客户端怎么对齐」（F10）—— 只管网关本身的判定。

## 规格

### SR-F9.1 写入前必须过闸；被闸拦下时必须给出「怎么解」而不是只报错

**规则**：任何写操作在落盘前必须依次通过计划闸、超载闸、空洞闸、审查闸。任一道拦下时，返回体必须同时包含：拦下的原因、判定依据（具体是哪一页、哪个数字、哪条引用）、以及**可执行的解法**。只返回「不允许」视为违反。

**为什么是这条线**：写入是唯一不可逆的动作。历史上被拦下但不知道怎么办时，模型的反应是反复重试同一个调用 —— 四次重试全被同一道闸挡住，白烧一轮上下文。

**违反长什么样**：返回 `{ ok: false, error: 'page overloaded' }` 而不说超载阈值是多少、超了多少、该删还是该拆页。

### SR-F9.2 一次写入必须整批原子：要么全成，要么一个都不写

**规则**：一批改动包含多个操作时，任何一个失败必须导致整批放弃。不得出现「前三个改成功了、第四个失败」的页面。写入完成前不得让读者看到中间态。

**为什么是这条线**：半成品的页面比没改更糟 —— 读者会看到一半新一半旧的内容，且没有任何标记说明它是坏的。

**违反长什么样**：逐条写库，第四条报错后返回 `{ ok: false, applied: 3 }`。

### SR-F9.3 写入必须被独立校验，不得信任调用方自述

**规则**：写完必须重新读回来，用与写入**不同的**路径做结构校验（元素 id 唯一、尺寸为正、必填字段存在），并把校验结论作为返回值的一部分。调用方说「我改好了」不构成证据。

**为什么是这条线**：写入路径的 bug 会写出合法 JSON 但结构非法的页面，而这种页面在渲染时才炸，那时已经离写入很远。

**违反长什么样**：写完直接返回 `{ ok: true }`，不做回读，不做结构校验。

### SR-F9.4 状态必须能从数据库读回来核对，不得只信进程内状态

**规则**：任何关于「数据现在是什么」的断言，必须以数据库为准。进程内缓存可以加速，但不能作为判据；两者冲突时以数据库为准，且必须能发现冲突。

**为什么是这条线**：进程内状态在重启后清空、在多进程下分裂。曾经出现「工具说改完了、数据库里没有」和反过来的情况，而两边都自认为是对的。

**违反长什么样**：工具返回上一次写在内存里的结果，不查库。

### SR-F9.5 自检结论必须指向可复查的落点

**规则**：写入后的自检结论必须给出读者或开发者能自己去查的位置：哪张表、哪一行（主键值）、哪个字段。不得只给「已更新」。

**为什么是这条线**：没有落点的「成功」无法证伪，等于没有自检。

**违反长什么样**：返回 `{ ok: true, message: '更新成功' }`。

### SR-F9.6 写入必须是 CAS：旧值不匹配就拒绝，不得覆盖他人改动

**规则**：写入必须带旧值作为比对条件。旧值不匹配时整条失败，返回「这一页在你编辑期间被别人改过了」，并要求重新读取后再改。不得用「后写覆盖」策略。

**为什么是这条线**：两个客户端（旧 Web UI 与 DSH 面板）会同时看同一页。没有 CAS 时，后手的保存会静默吃掉先手的修改，而且双方都看不到自己吃掉了什么。

**违反长什么样**：`update ... set data = $1 where stage_id = $2 and id = $3`，不带旧值条件。

### SR-F9.7 写入必须默认只算差集、不落盘，落盘必须是显式选择

**规则**：改页面的调用默认只返回差集（新增/删除/移动/改尺寸/改文字/改样式），不写库。写库必须由调用方显式选择。差集必须能区分「这次改动引入的」与「改前就存在的」。

**为什么是这条线**：模型对版面后果的预估不可靠。先看差集再决定落盘，把「不可逆」变成「可预演」。另外，把改前就有的问题算到这次改动头上，会让模型去做无意义的修补。

**违反长什么样**：一调用就落盘；或返回「有 5 个版面问题」而不说这 5 个是不是这次带来的。
