# F6 真浏览器抓取

## 域的范围

管「把别人家的网页变成能读、能核查、能接着用的文本」这条路的约束：渲染要真、来源要能核、拒绝要有据、看与存要分开。
不管检索与展开（F5），也不管这些能力什么时候被注册进工具表（F8）—— 只管一次抓取本身该产出什么。

## 规格

### SR-F6.1 抓取必须走真浏览器渲染，能拿到 JS 执行后的 DOM

**规则**：抓取必须在真实浏览器引擎里加载页面、等脚本执行完，再从渲染后的文档里取正文。不得用单次 HTTP 请求拿到的原始 HTML 代替渲染结果。等待渲染的时间必须可调，默认值不得为 0。

**为什么是这条线**：现在的网页大量内容由脚本注入，原始 HTML 只是挂载点和一堆 `<script>`。用一次性 HTTP 抓取时，对这类站点的结果是「请求成功、正文为空」—— 一个看起来正常、实际什么都没读到的返回。等待时间是必需的参数：不等就取，取的还是首屏空壳。

**违反长什么样**：对一页由前端框架渲染的站点返回「正文 0 字符」，却报告状态 200。

### SR-F6.2 抓取结果必须带可核查的来源标识（最终 URL、状态、耗时）

**规则**：任何一次抓取返回必须同时给出：最终 URL（重定向之后真正打开的那一个，不是请求时那一个）、HTTP 状态、渲染取文的耗时、正文字符数、以及是否被截断。这些字段必须随正文一起返回，不得只写进日志。

**为什么是这条线**：75 次抓取实测里 7 次 404、1 次 403、2 次重定向超限 —— 失败在这个能力上是常态而不是异常。没有最终 URL，读者无法核对「你读的是不是我要的那页」；没有状态与耗时，一次超时和一次空页面在返回体里长得一模一样。

**违反长什么样**：返回一大段正文，不说它是从哪个地址、什么状态、花了多久拿到的。

### SR-F6.3 反爬/风控判定只允许作用于正文抽取，不得因裸词误伤整页

**规则**：反爬与风控的判定对象必须是抽取后的正文（必要时加上标题），不得对整页原始 HTML 做子串匹配。判定必须带最小正文长度阈值：正文短于阈值时才允许判为拦截。命中词必须来自可维护的词表，不得散落在判定逻辑里。

**为什么是这条线**：历史上判定曾对整页 HTML 做子串匹配 —— `<script>` 里出现一个 `captcha` 字符串，整页就被判成拦截。实测 2 次就是这样被误伤的：页面本身是正常内容，被拒绝的理由是它引用了带这个词的脚本。对渲染后的正文判定，噪音源就消失了；再叠一层长度阈值，短正文才可能是真的拦截页。

**违反长什么样**：一页正常的技术文档因为页脚脚本提到验证码，被判为「被反爬拦截」并整页丢弃。

### SR-F6.4 「看」与「存」必须是两个动作，预览不得自动持久化

**规则**：只读地看一页（返回渲染正文供判断）不得写入任何持久化存储，不得在材料库里留下条目。落成材料必须是一次显式的、独立的动作。看动作返回的正文不得被当成「已保存」，也不得被后续引用当作可续读的对象。

**为什么是这条线**：看是高频动作、存是低频动作，把两者绑在一起会用一个试探性请求污染材料库 —— 而材料库里的东西会进后续的上下文。分开之后，「先看一眼值不值得留」不需要付出任何持久化代价，判断权留在调用方手里。

**违反长什么样**：只是想确认一下页面讲什么，材料列表里却多出一条再也不会被用到的记录。

### SR-F6.5 预览必须有字数上限，正文抽取不受该上限约束

**规则**：返回给模型的预览必须有固定字数上限，且上限值必须与正文抽取的长度限制分开定义。抽取并保存的正文不得被预览上限截短。当返回内容被截断时，必须明说「已截断」并给出总长度与继续读的位置。

**为什么是这条线**：预览恒 2000 字符，而抓回来的正文平均 17443 字符 —— 只看预览等于只读了 11%，这个比例必须被写进返回里，否则模型会拿 11% 当 100% 去描述整页。反过来，如果抽取本身也被这个上限卡住，存下来的就只有开头一段，续读也就无从谈起。两个上限服务两个目的，混成一个就会同时坏掉两件事。

**违反长什么样**：返回 2000 字符后直接结束，既不提总长也不给续读位置；或存进材料的正文也只有 2000 字符。
