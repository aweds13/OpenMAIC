# conventions.md — 横切约定

> 这些规则跨所有域，所以在域文件里重复写会走样。**每条规则必须标注来源 N**（检查器硬性要求）。
> 规则本身是可判定的：「看到了就算违反」，不写「尽量」「建议」。

## 一、判定与证据

- 任何结论都必须带**命令 + 读数**；不能复现的结论不许写进文档。来源：N19、SR-NF1
- 拿不准就写「不知道」，不许用「应该」「大概」「理论上」。来源：N19、SR-NF1
- 测试红的判决必须分三类：**真失败** / **环境噪声**（并发超时、路径分隔符）/ **基线同样红**。分类必须给对照读数。来源：N19、SR-NF1
- 判据必须能证明它看得到东西：打「这次实际检查了 85 条」，检查数为零同样算失败。来源：N19、SR-NF1

## 二、不静默降级

- 能力没配置 → 工具**不注册**，提示词里**不提**；不许注册一个永远返回错误的工具。来源：N15、SR-F8.2
- 配置了但对方不可达 → 工具返回结构化失败（`not_configured` / `error`），不许伪装成功。来源：N15、SR-NF6
- 下游产出不足（如题量不够）→ **报错**，不许把少的当成的。来源：N6、SR-F3.2
- 截断必须明说：给出「已截断，总长 N」而不是让读者以为读完了。来源：N12、SR-F6.5

## 三、提示词与上下文

- 系统消息在同一会话内**逐字节不变**；会话级材料不进系统提示词。来源：N16、SR-F7.2、SR-F7.3
- 工具名清单从**真正装出来的工具**派生，不手写第二遍。来源：N15、SR-F8.3
- 工具描述里不许提没注册的工具名。来源：N15、SR-F8.3
- 不可信内容（网页正文、材料、文档片段）只当**数据**，不当指令；提示词必须明写这一点。来源：N10、SR-NF5

## 四、工具参数

- 参数 schema 必须严格：拒绝额外键，不接受的组合要显式拒绝并说明。来源：N15、SR-NF4
- 每个参数必须有范围约束（`minimum` / `maximum` / `enum`），不许放任自由字符串。来源：N15、SR-NF4
- 失败必须可归因到四类之一：`not_configured` / `blocked` / `not_found` / `error`。来源：N15、SR-NF6

## 五、写入

- 写入前过闸；被拦时给「怎么解」，不只给「不行」。来源：N18、SR-F9.1
- 一次写入整批原子：中途失败不留半成品。来源：N18、SR-F9.2
- 写入必须被独立校验，不信任调用方自述。来源：N18、SR-F9.3
- 写入是 CAS（旧值不匹配就拒绝），默认只算差集不落盘。来源：N23、SR-F9.6、SR-F9.7
- 改版面必须报**差集**（新引入 / 修掉 / 未变），不许把改前就有的问题算到这次改动头上。来源：N23

## 六、数据与真源

- 真话在数据库里；进程内状态只是缓存，不能当判据。来源：N19、SR-F9.4
- 同一份数据只有一个真源；新宿主不做第二份存储。来源：N21、SR-F10.4
- 「当前页」这类瞬时状态宁可**空**也不猜；缺失时必须明说没有。来源：N22、SR-F10.6

## 七、跨平台与工程

- 判据必须 Windows 与 Linux 同一套；不许依赖 `\` 或 `/` 之一。来源：N19、SR-NF8
- 长命令必须落日志文件再读，不许用管道截断（中途看不到进度且中断后什么都拿不到）。来源：N19、SR-NF1
- 批量改文件必须**先按类型过滤**再改；绝不对 `git ls-files` 全集做字节替换（二进制会被静默损坏）。来源：N19、SR-NF1
- 提交只用 `git add <明确文件>`，不用 `-A`。来源：N19、SR-NF1
