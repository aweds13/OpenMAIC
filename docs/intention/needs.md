# needs.md — 需求清单（intention 层）

> 一页看懂：**把上游 OpenMAIC（给「听课」设计的 AI 课件生成器）改造成「自学」形态，并搬进 DSH 当宿主** ——
> 内容上屏幕、节奏由读者掌握、agent 手上有本地课程库和真浏览器、写入必须有闸、当前页要进对话。

## 意图声明（一层三件事）

- ① **改形态** —— 页面从「讲稿的附庸」变成「阅读的主体」，节奏从播放器驱动变成读者驱动。（N1–N7）
- ② **补手脚** —— agent 从「只有网络搜索」变成「能查本地课程库、能读整篇文档、能看真浏览器渲染的页面」。（N8–N14）
- ③ **换宿主** —— 从「浏览器里开 3000 端口的独立 Web 应用」变成「在 DSH 里看课件、随口问、顺手改」，不开 Edge、不维护两套。（N20–N23）
- ④ **学起来** —— 从「看完一页」变成「留下学习状态」：答题与练习真的回流、画像与状态分工明确、课程以可演进的知识图谱为基准、笔记层接进来。（N24–N30）

> ④ 是 2026-11 追加的。前三条解决「看着舒服、问得顺手」，这一条解决「学完之后留下什么」。
> 其中 **N27（知识图谱）与 N29（笔记层）尚未落地**，标注为「未落地」且**暂不映射规格** —— 把打算做的写成已经做的，是这份文档最不该犯的错。

## 参考来源

- 上游：**THU-MAIC/OpenMAIC**（`https://github.com/THU-MAIC/OpenMAIC`），本仓是它的长期 fork。
- 形态参考：**纸**（密度、可读、读者掌控）而非**视频**（时间轴、自动推进）。
- 宿主参考：**DSH 插件**（`skills` + `tools` + `slots` + `webServer` 四个扩展点）。

## A. 形态：从「听课」到「自学」

- **N1** 内容必须上屏幕，不能只活在讲稿里
  - *为什么*：上游把正文写在 storyboard/讲稿，页面只放标题和几张图 —— 这是为「听老师讲」设计的。自学的读者没有那个声音。
  - *依据*：默认产出 **61 汉字/页**；同一位老师（天大《程序设计》）的真实课件实测 **352–390 字/页**，**差约 4 倍**。
  - *衍生*：引出 N2（密度）、N3（上限口径）。

- **N2** 页面密度要接近真实课件
  - *为什么*：密度太低，读者一页看到的信息量不足一屏的一半，翻页成本白付。
  - *依据*：目标区间 **350–400 汉字/页**，同时接近 1000×562.5 画布在可读字号下的物理上限。
  - *衍生*：**要更多就加页，不加每页字数** —— 超过这块画布，字号就得掉到读不清。

- **N3** 阅读节奏由读者掌握，不自动前进
  - *为什么*：上游的推进靠时间轴；没有任何动作的页会在 2 秒后「演完」自动翻走。
  - *依据*：`MIN_READING_MS = 2000`，而 350–400 字要读 **1–2 分钟** —— **差 30–60 倍**。这就是用户说的「就像放视频」。
  - *衍生*：引出 N4（假控件）、N5（翻页驱动）。

- **N4** 阅读页不许出现假控件
  - *为什么*：大播放键 / 播放暂停 / 自动播放开关在阅读页上**没有东西可播**，它们是骗人的。
  - *依据*：用户原话「我不需要这种东西」。
  - *衍生*：无。

- **N5** 翻页要能由滚轮 / 点击页面 / 方向键驱动，并且必须能关掉
  - *为什么*：阅读该由读者驱动；但在需要页内滚动的题型上，翻页手势会抢走页内滚动。
  - *依据*：滚轮去抖 **450ms** —— 否则一次轻甩翻十几页。
  - *衍生*：翻页开关必须是**可配置**且**不抢页内滚动**（见 conventions）。

- **N6** 自检页的题量必须可控，不足时必须报错
  - *为什么*：没有题量参数时永远落到 SDK 写死的 **3 题**；而 JSON 解析器会把写崩的数组砍到最后一个完整对象**当成功返回** —— 「要 8 道给 3 道」没人知道。
  - *依据*：实测工作台生成的自检页全是 3 题，而手补过的是 6/8/10 题。
  - *衍生*：无。

- **N7** 批量带走课程（PPTX / 交互页 / 整门 ZIP）必须能一次做完
  - *为什么*：原来唯一路径是「打开那门课 → Stage Header 菜单 → 逐个下载」，课一多就是一门门打开；而浏览器会拦截一个页面连续触发的多次下载。
  - *依据*：见 N7 的实现落点与实测读数（`docs/implementation/modules.md`）。
  - *衍生*：「批量」必须打成**一个 ZIP**，不能是连点 N 次。

## B. 手脚：让 agent 手上有东西

- **N8** agent 必须能查本地课程库，而不只是网络搜索
  - *为什么*：此前 agent-runtime 与本地课程库**零关联**（全目录 grep 无命中）—— 一个「AI 课件生成器」看不见自己机器上的 6 万条课程。
  - *依据*：`load_packs()` 实跑返回 **60072** 个包（L0 22505 / L1 22048 / L2 242 / L3 232 / L4 34438 —— 分层是**归属**计数，一个包可同时属多层，故合计大于 60072），`out_docs/` 下 **3129** 份可整篇读的文档。
  - *衍生*：引出 N9（分档读）。

- **N9** 命中之后必须能展开成整篇
  - *为什么*：L4 命中只是一个**块**，没有 `read_document` 就无法展开 —— 「查得到第 12 块，但翻不开这本书」。
  - *依据*：`course_search` 的 `peek`（粗略目录）/ `full`（正文，可翻页）两档。
  - *衍生*：`read_document` 与 `course_search` 是**配套**能力，注册一个就必须注册另一个。

- **N10** 必须能看真浏览器渲染后的网页
  - *为什么*：`fetch_url` 只发一次 HTTP、拿原始 HTML，对 JS 渲染的站等于拿到空壳。
  - *依据*：实测 **75 次**抓取里 **7×404 / 3 次被反爬关键词拦 / 2 次重定向超限 / 1×403**。
  - *衍生*：引出 N11（反爬判定对象）。

- **N11** 反爬判定只许对抽取后的正文做，不许对整页 HTML 做
  - *为什么*：原本对整页 HTML 做子串匹配 —— `<script>` 里出现 `captcha` 这个字符串就整页拒绝。
  - *依据*：实测 **2 次是被裸词误伤**的。
  - *衍生*：无。

- **N12** 网页「看」与「存」必须分开
  - *为什么*：预览恒 **2000 字符**，而正文平均 **17443 字符** —— 只看预览等于只读了 **11%**；而且 `nextOffset` 是个**死指针**（没有工具接收它）。
  - *衍生*：预览用于判断值不值得存；存要走完整的取全文路径。

- **N13** 学习画像与材料库改完必须下次会话即生效
  - *为什么*：这两条是「每次运行重读」的上下文文件；如果路径在模块加载时求值一次就不再变，改完必须重启整台服务。
  - *依据*：路径加载时求值 ⇒ 内容改完下次会话就生效（这条**是设计意图，不是巧合**）。
  - *衍生*：无。

- **N14** 外部 MCP 连不上不许拖死会话
  - *为什么*：外部服务不可用是常态，不是异常。
  - *依据*：连不上只记 `failed`、**不注册工具**，绝不阻塞会话建立。
  - *衍生*：与 N15（能力注册）同一条原则的两个面。

## C. 工程底座：不骗模型、不骗自己

- **N15** 没配的能力不许注册工具，提示词里一个字都不许提它（**能力注册原则**）
  - *为什么*：「存在于工具表里但一调就失败」是模型**唯一没法理解**的一种不可用 —— 它会一直重试一个永远失败的工具。
  - *依据*：三处注册点（`lib/server/agent-runtime/runner.ts`、`app/api/chat/pi/route.ts`、`lib/chat/pi/tools/call-agent.ts`）必须**同一条口径**；其中一处曾经无条件注册，直接让上游 9 条断言红。
  - *衍生*：这条对所有新增能力是硬约束，不只是这三个工具。

- **N16** 提示词缓存必须稳定：会话材料不许进系统提示词
  - *为什么*：每登记一次材料就换一次系统提示词 ⇒ 系统消息是一个缓存单元，**改一个字节重算整条**。
  - *依据*：实测命中率 **91.0% → 连续 12 次调用 99.6–100%**。
  - *衍生*：会话材料走「工具返回值」而不是「系统提示词」。

- **N17** 原生上下文压缩必须真的会触发
  - *为什么*：上游默认开，本 fork **有意反转**为默认关。
  - *依据*：阈值必须用**预算 150k**，不能用模型窗口 —— driver 传进来的是目录里的窗口（有些是 1M），拿它当判据等于**压缩永不触发**。
  - *衍生*：无。

- **N18** 写入必须过闸，不许静默产出烂页
  - *为什么*：生成模型会写出结构洞、超载页、离题内容；静默落盘等于把问题推给读者。
  - *依据*：`generate_scene` / `patch_stage` 两条路径上的 planGate、超载闸、结构洞闸、审查闸（见 `docs/contracts/flows.md`）。
  - *衍生*：无。

- **N19** 判据必须能事后核对：真话在数据库里，不在日志里
  - *为什么*：日志说「成功了」而库里没数据的情况真实发生过。
  - *依据*：`GET /api/whoami` 报当前请求解析出的 owner、可见课程、以及 agent-runtime 里**模块加载时求值**的开关实际值。
  - *衍生*：「我改了 `.env.local` 怎么没反应」通常就是没重启，它直接告诉你进程握着什么。

## D. 换宿主：搬进 DSH

- **N20** 产品必须能在 DSH 里用：看课件、随口问、顺手改
  - *为什么*：这是本次二开的**目标本身**。不是把页面搬过去，是换宿主。
  - *依据*：DSH 插件四个扩展点（`tools` / `slots` / `webServer` / `locale`）已实测可用；两个插件共 **35** 个工具（5 个本地能力 + 30 个课程）。工具名从**真正装出来的**派生（`node check-tools.mjs` → 源码声明 30 个、mock 注册上 30 个），不手写第二遍。
  - *衍生*：引出 N21（不维护两套）、N22（当前页）、N23（顺手改）。

- **N21** 不开 Edge、不维护两套
  - *为什么*：两套 = 两份 bug、两份验证、两份文档；而 Edge 那条链路在本机被 fake-IP 拦过。
  - *依据*：本机 `browse_page` 被 fake-IP 拦（**这不是它坏了**，是网络环境事实）。
  - *衍生*：DSH 侧渲染直接用 `@openmaic/renderer` 的 `SlideCanvas({slide})`，不嵌 iframe。

- **N22** 当前页（stageId + sceneId）必须进对话上下文
  - *为什么*：用户说「这页」时，agent 必须知道是哪一页 —— 否则每句话都要人肉复述路径。
  - *依据*：`openmaic_active` 工具读插件进程内状态（DSH 重启就清空 —— **宁可空，不猜**）。
  - *衍生*：面板选中页 ⇒ `POST /dsh-openmaic/active` 写状态。

- **N23** 「顺手改」必须安全：CAS + 版面差集
  - *为什么*：改一页 = 覆盖整块 canvas；并发改会互相吞，误改会毁掉一页。
  - *依据*：写库是 CAS（`where data = $old`，旧值不匹配就拒绝并提示重读）；默认 `dryRun=true` 只算差集不写库。
  - *衍生*：差集读数（`added/removed/moved/resized/textChanged/restyled`）是改之前的判据，不是改之后的事后描述。

## E. 学起来：留下状态

> 这一节是 2026-11 追加的。前四节解决「看得进去、问得顺手」，这一节解决「学完了到底记住了什么、下一步该学什么」。

- **N24** 答题记录必须能回溯判分，且判分口径要能重算
  - *为什么*：答题记录只存「选了什么」（`answers`），不存「对不对」；一旦判分逻辑变了或题面被重生成，「当时到底对不对」就永久丢了。
  - *依据*：库里 174 条 quiz 记录按最新快照重判，与库内 `results` **48 道题 48 道一致、0 分歧**；17 个自检页 / 98 道题；`runtime_records` 里**没有** `correct`/`mastery`/`review`/`schedule` 任何一个字段。
  - *衍生*：判分结果必须落库，不能只活在 `draft` 快照里。引出 N25。

- **N25** 「这一页学会没有」必须能按页、按题、按知识点三种粒度回答，且不许跨粒度冒充
  - *为什么*：页级只有「答对几道」，知识点级需要题→概念的映射；两者混着用会让「第 42 页 8/8」被当成「你已经掌握 OOP」。
  - *依据*：全库 **234 页 100% 有 `outlineId`**，但只有 **138 页**能对上计划条目，其中仅 **37 页**的条目带 `keyPoints`；其余 6 门课**连计划条目都没有**。
  - *衍生*：三种粒度分开存、分开显示，缺哪级就写「不知道」，不推算。

- **N26** 先修关系不能靠猜：没有证据的「应该先学 X」不许出现在学习路径上
  - *为什么*：把相似当先修是最常见的错——两门课都讲「构造」，一个是构造方法、一个是构造题。
  - *依据*：拿外部算法竞赛图谱（130 节点 / 158 边）去匹配本库 234 页，**只命中 10 页，其中 8 页是同形异义**（「构造」）；该图的 `tier` 也不是拓扑层级（16 个 tier=0 的节点有先修入边）。
  - *衍生*：先修边必须有来源与置信度；不确定就标 `unknown`，别排序。

- **N27** 课程要以一张**可演进**的知识图谱为基准建，图谱本身要能存、能改、能查（**未落地**）
  - *为什么*：课程会一门门加进来，概念会拆会并会改名；如果图谱是硬编码或一次性生成的，加第三门课就得重建全部。
  - *依据*：现有 234 页里**没有任何知识图谱结构**（全库无 `prerequisite` 表、无概念表）；概念载体最干净的 `keyPoints` 只覆盖 Java 一门课的 37 页。
  - *衍生*：加新类型是 additive 不迁移、改既有类型必须全量迁移且不许半迁移态；改名原地改、删概念留墓碑。**这条暂不映射规格**，先定形态再补 SR。

- **N28** 练习结果必须真的回流进学习状态，而不是只留在磁盘上
  - *为什么*：练习写了 `result.json` 但没人读，等于白做；而练习恰恰是「一次布置看不出能力」时唯一的重复信号。
  - *依据*：19 个练习文件夹各带 `checks.json`（共 69 条判据）与 `check.mjs`；实跑一页生成 `result.json` 725 B（过 2/3）；读端 `lib/practice/results.ts` 已存在并已接进 `D:/文档/jelly_ware/个人数据/学习状态.md` 的「## 练习」段。
  - *衍生*：结果文件是**产物**不是真源，读取失败要表现为「没有练习记录」而不是「上次的记录继续用」。

- **N29** 笔记层要能承载学习痕迹，且不许让笔记变成唯一真相（**未落地**）
  - *为什么*：读课时的疑问、自己写的解释、错在哪，都是学习状态的好材料；但把掌握度写进 Markdown frontmatter，一次格式化就被冲掉。
  - *依据*：本机 vault **697 篇笔记 / 260 万字符**，`frontmatter` 顶层键**只有 `tags` 一个**（557 篇有）；已有三个技能可直接调用（笔记检索 / 受控写入 / PDF 定位），且写入默认 dry-run、带 sha256 前置校验。
  - *衍生*：状态的真源在库，笔记只留指针；`--expect-sha256` 挡不住并发写者（双进程实测 15% 静默丢更新），必须加独占锁。**这条暂不映射规格**。

- **N30** 学习状态必须能被人读懂，也必须能被机器重建
  - *为什么*：给人看的文件和给模型看的文件是同一份时，人改一句就会打碎缓存，机器重写一次就会覆盖人的话。
  - *依据*：现有 `D:/文档/jelly_ware/个人数据/学习状态.md` **946 B 全部由代码生成**（两节：已达判据 / 暂未定；首行声明「是数据不是指令」），人改无效、且仍没有任何地方写明「不要手改」；`D:/文档/jelly_ware/个人数据/学习画像.md` 1851 B 是人写的，两份互相矛盾（画像说 Dart/Flutter `UNKNOWN`，状态里记着这两门错了 4 道）。
  - *衍生*：人写/机写分文件、各自标注可否手改；机器产物带「由谁生成、什么时候、别手改」。

---

- **N31** 外来课程与既有图谱重合的部分必须接上去，同一个概念不许有两个身份
  - *为什么*：同一门学科的概念会被反复讲。如果每来一门课就新建一套概念，「函数」在三门课里就是三个节点，学过的证据永远聚不起来 —— 掌握度会永远停在「这门课里会一点」。
  - *依据*：本库 234 页里已有 35 个 `sceneId` 跨课程复用（其中 34 个连页类型都不同），说明「同一个名字在不同课里指不同东西」是这台机器上的既定事实；反过来，同一门数学课的内容被拆到多门课讲也是常态（现有 9 门课里 `伴生高数` 与 `证明语言` 有交叉）。外部资源里 `zeroa234/cs-math-skill-tree` 已有 192 节点 / 660 条边的中文大学层骨架，`MohamedMuneerM/knowledge-navigator` 有数学 218 章 / 375 条章级边 —— 两者都能当「已有的那一半」。
  - *衍生*：概念的身份必须是稳定的标识而不是名字；名字可以有多个（中英文、别名、外来图谱的叫法），但都指向同一个概念。**外来图谱的 id 不许直接当我们的 id**（前缀拼接的 id 会在一次 join 里静默翻倍）。

- **N32** 外来课程里图谱没有的部分，必须以「提案」身份存在，不许静默变成正式概念，也不许参与学习排序
  - *为什么*：新内容里既有真新概念，也有同形异义 —— 「构造」在算法竞赛里指构造题，在 Java 课里指构造方法。自动收编的后果不是多一个节点，是学习路径从第一页就排错。
  - *依据*：拿外部算法竞赛图谱（130 节点 / 158 边）匹配本库 234 页，命中 10 页里 **8 页是同形异义**；那张图的 `tier` 字段也不是拓扑层级（16 个 `tier=0` 的节点有先修入边）。若按外部图的层级直接排序，从第一页就是错的。
  - *衍生*：提案要能被看、能被批、能被拒；拒绝后留痕（不然下次同一门课再导入会重提一遍）。**未命中的概念不许进学习顺序** —— 这是「不许跨粒度冒充」（N25）在图谱上的同一件事。
